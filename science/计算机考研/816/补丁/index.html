    补丁 1：ISO/OSI 参考模型与 TCP/IP 模型深度对比（大纲 一(二)3）

    1. 三类模型层次对应与第 5、6 层核心功能：
    2. OSI 七层模型（从下往上）：物理层、数据链路层、网络层、运输层、会话层（Session Layer）、表示层（Presentation Layer）、应用层。
    3. 会话层核心功能：管理主机进程间的会话，负责建立、管理和终止会话，并通过插入同步点（检错点 Checkpoints）实现数据同步与断点续传。
    4. 表示层核心功能：处理两个通信系统中交换信息的表示方式（语法转换），主要包括三大功能：①数据格式与编码转换（如 ASCII 与 Unicode 转换，解决不同机器字节序大小端差异）；②数据加密与解密；③数据压缩与解压缩。

    5. TCP/IP 四层模型：网络接口层（对应物理层 + 数据链路层）、网际层 IP、运输层（TCP / UDP）、应用层（合并了 OSI 的会话层、表示层和应用层）。

    6. OSI 模型与 TCP/IP 模型在“面向连接 vs 无连接”上的核心差异（高频单选！）：

    模型名称 网络层（Network Layer）支持的服务 运输层（Transport Layer）支持的服务 核心设计哲学对比
    ISO/OSI 参考模型 同时支持 无连接 和 面向连接 仅支持面向连接 的通信 通信可靠性的重担交给网络层或严格面向连接的运输层。
    TCP/IP 模型 仅支持无连接 的服务（IP 数据报） 同时支持 无连接（UDP） 和 面向连接（TCP） “沙漏模型 / 端到端原则”：网络核心（IP层）保持极简无连接，复杂的可靠传输与是否建连的选择权完全交给端系统的运输层！

    补丁 2：物理层数字编码与调制波形全解析（大纲 二(一)3）

    1. 数字数据编码为数字信号（基带传输 6 大编码规则与判别特征）：
    编码名称 电平跳变规则（看图识波形核心依据） 是否自带时钟同步信号 编码效率（波特率与比特率关系） 典型应用场景
    不归零制（NRZ） 高电平代表 1，低电平代表 0（或反之），整个码元周期内电平保持不变。 否（遇到连续 1 或连续 0 时完全无跳变，收发双方极易丢失时钟同步，且存在直流分量） \(100\%\)（\(B = R\)） 计算机内部近距离含独立时钟线的并行总线
    反向不归零编码（NRZI） 信号电平翻转（跳变）代表 0，电平保持不变代表 1。 连续 0 可同步，但连续 1 仍无跳变 \(100\%\)（\(B = R\)） USB 2.0、光纤 FDDI
    归零制（RZ） 正脉冲代表 1，负脉冲代表 0，但每个码元周期的中间时刻电平必须归回到零电平。 是（但占用了一半归零时间，且共有 \(+1, 0, -1\) 三种电平状态） \(50\%\)（\(B = 2R\)） 早期低速同步信道
    曼彻斯特编码（Manchester） 每个码元周期的正中间时刻必须发生一次电平跳变：中间向上跳变代表 0、向下跳变代表 1（或反之，依约定而定）。中心的跳变既作时钟信号，又作数据信号！ 是（自同步能力极强，无直流分量） \(50\%\)（每传 \(1\text{ bit}\) 需 \(2\) 个脉冲码元，波特率 \(B = 2R\)） 传统 \(10\text{ Mbit/s}\) 以太网（10BASE-T）
    差分曼彻斯特编码 每个码元周期的正中间时刻恒有一次跳变（仅作时钟同步）；表示数据看每个码元开始边界处是否跳变：码元起点处有跳变代表 0，起点处无跳变（电平延续上一码元末尾）代表 1！ 是（抗干扰性比曼彻斯特更强，且不怕两根导线极性接反） \(50\%\)（波特率 \(B = 2R\)） IEEE 802.5 令牌环局域网
    4B/5B 编码 将每 \(4\text{ bit}\) 原始数据查表映射为 \(5\text{ bit}\) 编码（从 \(2^5=32\) 种组合中精选出 16 种不会出现超过连续 3 个 0 的组合），再配合 NRZI 发送。 是（解决了 NRZI 连续 1 不跳变问题） \(80\%\)（波特率 \(B = 1.25R\)） \(100\text{ Mbit/s}\) 快速以太网（100BASE-TX）
    1. 数字数据调制为模拟信号（频带传输 4 大调制方式）：
    2. 调幅（ASK / 2ASK）：用载波振幅的有无（或大小）表示 1 和 0。实现最简单，但抗噪声干扰能力最差。
    3. 调频（FSK / 2FSK）：用两种不同的载波频率 \(f_1, f_2\) 表示 1 和 0。抗干扰能力强，但占用频带较宽。
    4. 调相（PSK / 2PSK / QPSK）：用载波初始相位的改变表示数据。分为绝对调相（如 \(0^\circ\) 表 0、\(180^\circ\) 表 1）和相对调相（DPSK）。QPSK（正交相移键控）采用 4 种相位（\(M=4\)），每个码元携带 \(\log_2 4 = 2\text{ bit}\) 信息。
    5. 正交振幅调制（QAM）：将 振幅（ASK）和相位（PSK）结合起来同时调制。若某个星座图有 \(m\) 种振幅和 \(n\) 种相位，且可组合出 \(M\) 个星座点（如 16-QAM 有 \(M=16\) 个点，64-QAM 有 \(M=64\) 个点），则每个码元携带 \(\log_2 M\text{ bit}\) 信息，数据传输速率 \(R = B \log_2 M\)。

    补丁 3：纠错编码——海明码（Hamming Code）完整原理与手算模板（大纲 三(三)2）

    1. 码距（海明距离 \(d_{\min}\)）与检错/纠错能力定理（必背公式）：
    2. 两个等长码字之间对应比特位不同的个数称为两个码字的海明距离；整个编码集中任意两个合法码字海明距离的最小值称为该编码的码距 \(d_{\min}\)。
    3. 检错能力公式：为了检测出 \(e\) 个比特的错码，要求码距满足： $\(d_{\min} \ge e + 1\)$
    4. 纠错能力公式：为了纠正 \(t\) 个比特的错码，要求码距满足： $\(d_{\min} \ge 2t + 1\)$
    5. 同时检错与纠错公式（检出 \(e\) 位错，同时纠正其中 \(t\) 位错，且 \(e \ge t\)）： $\(d_{\min} \ge e + t + 1\)$

    6. 推论：奇偶校验码的码距 \(d_{\min} = 2\)（只能检出 1 位或奇数位错，不能纠错，\(t=0\)）；能纠正 1 位错的海明码最小码距为 \(d_{\min} = 2 \times 1 + 1 = 3\)！

    7. 海明码四步手算标准算例（考场直接套用）：

    8. 【例题】：已知 4 位原始数据位为 \(D_4 D_3 D_2 D_1 = 1010\)（按从低位 \(D_1=0, D_2=1, D_3=0, D_4=1\) 排列）。求：(1) 按偶校验构造海明码；(2) 若接收端收到的海明码第 6 位出错变为 1110110（位号 \(1\sim 7\) 从左到右或从低到高排列），如何定位并纠错？
    9. 【第一步：确定校验位位数 \(k\)】： 数据位 \(n = 4\)，代入海明不等式： $\(2^k \ge n + k + 1\)$ 当 \(k = 3\) 时，\(2^3 = 8 \ge 4 + 3 + 1 = 8\) 成立！故需要 \(k = 3\) 位校验位（\(P_1, P_2, P_3\)），海明码总位数为 \(n + k = 4 + 3 = 7\) 位（编号为第 \(1 \sim 7\) 位）。
    10. 【第二步：安放校验位与数据位的位置】：
      • 铁律：校验位 \(P_i\) 永远放在位号为 \(2^{i-1}\) 的位置上（即第 \(1, 2, 4, 8, 16 \dots\) 位）；其余位置按顺序填入数据位！

    二进制位号 001 010 011 100 101 110 111

    • 【第三步：分组异或求校验位 \(P_1, P_2, P_3\)（偶校验）】：
      • 分组技巧：看上表中的“二进制位号”——
      • 凡是二进制位号第 1 位（最低位 __1）为 1 的列（即第 \(1, 3, 5, 7\) 位），归 \(P_1\) 管： $\(P_1 = H_3 \oplus H_5 \oplus H_7 = D_1 \oplus D_2 \oplus D_4 = 0 \oplus 1 \oplus 1 = \mathbf{0}\)$
      • 凡是二进制位号第 2 位（中间位 _1_）为 1 的列（即第 \(2, 3, 6, 7\) 位），归 \(P_2\) 管： $\(P_2 = H_3 \oplus H_6 \oplus H_7 = D_1 \oplus D_3 \oplus D_4 = 0 \oplus 0 \oplus 1 = \mathbf{1}\)$
      • 凡是二进制位号第 3 位（最高位 1__）为 1 的列（即第 \(4, 5, 6, 7\) 位），归 \(P_3\) 管： $\(P_3 = H_5 \oplus H_6 \oplus H_7 = D_2 \oplus D_3 \oplus D_4 = 1 \oplus 0 \oplus 1 = \mathbf{0}\)$
      • 将算出的 \(P_1=0, P_2=1, P_3=0\) 填回表中，得到最终发送的 7 位海明码（按 \(H_1 \sim H_7\) 顺序）为：0 1 0 0 1 0 1。
    • 【第四步：接收端计算指错字（校验子 \(S_3 S_2 S_1\)）定位错位】：
      • 设在传输中第 6 位（\(H_6\)）由 0 翻转为 1，接收端收到的 \(H_1 \sim H_7\) 为 0 1 0 0 1 1 1。
      • 接收端对三组分别进行异或求指错字 \(S_1, S_2, S_3\)：
      • \(S_1 = P_1 \oplus H_3 \oplus H_5 \oplus H_7 = 0 \oplus 0 \oplus 1 \oplus 1 = \mathbf{0}\)
      • \(S_2 = P_2 \oplus H_3 \oplus H_6 \oplus H_7 = 1 \oplus 0 \oplus 1 \oplus 1 = \mathbf{1}\)
      • \(S_3 = P_3 \oplus H_5 \oplus H_6 \oplus H_7 = 0 \oplus 1 \oplus 1 \oplus 1 = \mathbf{1}\)
      • 将指错字按高位到低位排列得到二进制数 \(S_3 S_2 S_1 = \mathbf{110_2} = \mathbf{6}\)！
      • 指错字直接指出：第 6 位（\(H_6\)）发生了比特翻转！将该位取反（\(1 \rightarrow 0\)）即完成自动纠错（若 \(S_3 S_2 S_1 = 000\) 则表示无差错）。

    确认方式 逐帧确认 累积确认（Cumulative ACK）（允许捎带确认） 逐帧个体确认（Individual ACK）（绝不累积！）
    优缺点与适用场景 极简，但长时延高带宽下信道利用率极低 接收方无需大缓存、实现简单；但误码率高时会引发大量不必要的回退重传，浪费带宽 避免重复传送已正确到达的帧，传输效率最高；但接收方需复杂缓存与排序逻辑，且序号空间利用率为一半
    • 【为什么 SR 的窗口上限只能取到 \(2^{n-1}\)（即 \(W_T + W_R \le 2^n\)）？推导实例】：
    • 设用 \(n = 2\text{ bit}\) 编号（序号为 \(0, 1, 2, 3\)），则 \(2^{n-1} = 2\)。
    • 若违规令 \(W_T = W_R = 3\)（此时 \(W_T + W_R = 6 > 4\)）：发送方发出帧 0, 1, 2，接收方全部收到并缓存，此时接收窗口向前滑动 3 格，新接收窗口变为 [3, 0, 1]（注意：新接收窗口里已经包含了新一轮的序号 0 和 1！）。
    • 若接收方发回的 ACK0, ACK1, ACK2 全在路上丢失，发送方超时重传旧的帧 0，此时接收方的新窗口 [3, 0, 1] 正好允许接收序号 0，接收方就会把重传的旧帧 0 误当作新一轮的新帧 0 缓存收下！

    • 因此，为保证“旧发送窗口”与“完全滑动后的新接收窗口”没有任何序号重叠，必须满足 \(W_T + W_R \le 2^n\)；在发送窗口与接收窗口取相同最大值时，必有 \(W_{T\max} = W_{R\max} = 2^{n-1}\)！

    • 【信道利用率通用计算公式（适用于停等 / GBN / SR）】： 设发送 1 个数据帧的发送时延为 \(T_D = \frac{L_{\text{数据}}}{R}\)，单程传播时延为 \(\tau\)（往返时间 \(\text{RTT} = 2\tau\)），确认帧发送时延为 \(T_A\)（通常忽略 \(T_A = 0\)），发送窗口大小为 \(W_T\) 个帧： $\(U = \frac{W_T \cdot T_D}{T_D + 2\tau + T_A} \quad (\text{注意：若算出的 } U > 1\text{，则取 } U = 100\%\text{！})\)$

    • 若题目要求“使信道利用率达到至少 \(X\%\)（如 \(80\%\)），求发送窗口 \(W_T\) 至少为多少，以及帧序号至少需要几位比特 \(n\)”：
      1. 先由 \(\frac{W_T \cdot T_D}{T_D + 2\tau} \ge 0.8\) 解出最小整数 \(W_T\)；
      2. 若为 GBN 协议：由 \(2^n - 1 \ge W_T \Rightarrow 2^n \ge W_T + 1\) 求出最小比特数 \(n\)；
      3. 若为 SR 协议：由 \(2^{n-1} \ge W_T \Rightarrow n - 1 \ge \lceil \log_2 W_T \rceil\) 求出最小比特数 \(n\)！

    补丁 5：轮询访问（令牌传递协议）与广域网 HDLC 协议（大纲 三(五)3、三(七)3）

    1. 轮询访问介质访问控制：令牌传递协议（Token Passing，如 IEEE 802.5 令牌环网 / 802.4 令牌总线网）：
    2. 核心原理：物理拓扑可以是环型或总线型，但所有站点在逻辑上组成一个逻辑环。环上只有一个特殊的短控制帧称为“令牌（Token）”，沿着逻辑环单向逐站传递。
    3. 收发四步曲：
      1. 网络空闲时，只有空令牌在环上循环流动；
      2. 想要发送数据的站点必须等待捕获经过本站的令牌，将“闲令牌”修改为“忙令牌（数据帧）”，在后面附上数据发出；
      3. 数据帧沿环传遍所有站点，目的站点识别出自己的地址后复制一份数据帧到缓存，同时将该帧中的响应标志位置为“已收到”，数据帧继续沿环前进回到发送站；
      4. 发送站收到自己发出的帧后，检查响应位确认对方已收到，将自己发出的帧从环上回收撤除，并重新产生一个新的空令牌传给下一个站点（规定每拿一次令牌最多只能占有信道一个“令牌持有时间”，防止单站长期霸占）。

    4. 核心优缺点（与 CSMA/CD 对比必考）：

      • 优点：在重负载（通信量很大）时，绝对不会发生碰撞冲突，信道利用率可达 \(100\%\)，且每个站点获得令牌的最大等待时间是严格确定的（具有实时性保证）；
      • 缺点：在轻负载（没人发数据）时，站点也必须傻等令牌传到自己手里才能发，引入了不必要的等待延迟；且需维护令牌（防令牌丢失或重复令牌），控制复杂。

    补丁 6：网络层拥塞控制与路由器硬件体系结构（大纲 四(一)3、四(七)1）

    1. 网络层拥塞控制（开环控制 vs 闭环控制 vs 主动队列管理 RED）：
    2. 拥塞原因：对网络中某一资源（链路带宽、路由器缓存、处理机时间）的需求超过了该资源所能提供的可用部分，导致网络吞吐量随负载增加反而急剧下降，甚至跌为 \(0\)（称为死锁 Deadlock）。
    3. 两类控制方法：
      • ①开环控制（预防）：在设计网络时事先将可能导致拥塞的因素考虑周到，一旦系统运行起来就不再中途更改。
      • ②闭环控制（基于反馈环路动态调节）：监测网络系统何时何地发生拥塞 \(\rightarrow\) 将拥塞信息传给相关站点 \(\rightarrow\) 调整系统操作以消除拥塞。

    4. 路由器主动队列管理 AQM 与随机早期检测 RED（Random Early Detection）：

      • 传统路由器的“尾部丢弃（Tail-drop）”策略会等队列彻底占满才一刀切丢弃后续所有包，导致多条 TCP 连接同时超时进入慢开始，引发“全局同步（Global Synchronization）”现象，使网络流量忽大忽小剧烈震荡。
      • RED（随机早期检测）：路由器维护两个队列长度门限 \(TH_{\min}\)（最小门限）和 \(TH_{\max}\)（最大门限）：
      • 当平均队列长度 \(< TH_{\min}\) 时：不丢弃任何分组，正常入队；
      • 当平均队列长度 \(> TH_{\max}\) 时：丢弃所有新到达的分组；
      • 当平均队列长度介于 \([TH_{\min},\ TH_{\max}]\) 之间时：按照线性计算出的概率 \(p\) 随机丢弃新到达的分组，从而使个别 TCP 连接提前感知到轻微拥塞而个别减小拥塞窗口，彻底避免了全网 TCP 的全局同步现象！

    5. 路由器的组成结构与三种交换结构（大纲 四(七)1 高频单选！）：

    6. 两大核心职能模块：
      • ①路由选择部分（控制层面 / 控制部分）：核心是路由选择处理机，负责运行 RIP、OSPF、BGP 等路由协议，与其他路由器交换路由信息以生成和更新路由表，再由路由表导出供硬件快速查找的转发表（FIB）。此过程用软件实现，速度较慢（毫秒/秒级）。
      • ②分组转发部分（数据层面）：由三部分组成——输入端口、交换结构（Switching Fabric）、输出端口。根据转发表将输入端口收到的分组高速搬运到对应的输出端口。此过程用硬件（ASIC芯片）实现，速度极快（纳秒级）。
    7. 输入/输出端口的三层处理结构：输入端口依次经过“物理层比特接收 \(\rightarrow\) 数据链路层拆帧剥去 MAC 首尾 \(\rightarrow\) 网络层查转发表并排队进入交换结构”（输出端口顺序完全相反）。
    8. 交换结构的三种实现方式（从慢到快）：
      1. 通过存储器进行交换：第一代路由器，由 CPU（路由选择处理机）直接控制，把分组从输入端口复制到存储器，再从存储器复制到输出端口。每转发一个分组需经过两次系统总线，速度极慢。
      2. 通过总线进行交换：输入端口通过一条共享的高速内部背板总线直接把分组传到输出端口，无需 CPU 干预；但同一时刻总线上只能传一个分组，总线带宽成为瓶颈。
      3. 通过纵横交换结构（Crossbar Switch / 互连网络）进行交换：由 \(2N\) 条水平和垂直交叉的总线网格组成。只要多个输入端口去往的是不同的输出端口，就可以多对端口并行同时转发分组，无阻塞、吞吐率最高！
    9. 队头阻塞（Head-of-Line Blocking, HOL）：在输入端口队列中，排在队头的分组因为它的目标输出端口正忙（发生冲突）而不得不等待，导致排在它后面的、本来要去往其他空闲输出端口的分组也被死死堵在输入队列里无法前进的现象。

    补丁 7：链路状态路由算法——OSPF 与 Dijkstra 最短路径算法手算推演模板（大纲 四(二)3、四(五)4）

    1. OSPF 协议核心工作机制（五种分组与区域划分）：
    2. 链路状态构建：每个路由器通过洪泛法（Flooding，收到新链路状态就从除进入接口外的所有接口转发，并用确认机制保证可靠洪泛）向本自治系统（AS）内所有路由器发送“本路由器跟哪些邻居相连、以及该链路的度量代价是多少”。最终全网每个路由器都能建立起一个全网完全一致的链路状态数据库（LSDB，即全网完整拓扑图），然后各自以自己为根运行 Dijkstra 最短路径算法。
    3. OSPF 五种分组类型：①问候分组（Hello，每10秒发一次，发现和维护邻居可达性）；②数据库描述分组（DD，交换数据库摘要目录）；③链路状态请求分组（LSR，请求自己缺少的详细记录）；④链路状态更新分组（LSU，洪泛详细链路状态，最核心！）；⑤链路状态确认分组（LSAck，对 LSU 进行确认）。

    4. OSPF 区域（Area）两级层次结构：为使 OSPF 能用于规模很大的自治系统，将 AS 划分为若干个更小的区域（Area，用 32 位点分十进制标识）。洪泛仅限制在单个区域内部！其中标识符为 0.0.0.0（区域 0）的称为主干区域（Backbone Area），用来连通其他所有下层区域。
