#### 补丁 1：ISO/OSI 参考模型与 TCP/IP 模型深度对比（大纲 一(二)3）

1. **三类模型层次对应与第 5、6 层核心功能**：
   * **OSI 七层模型（从下往上）**：物理层、数据链路层、网络层、运输层、**会话层（Session Layer）**、**表示层（Presentation Layer）**、应用层。
   * **会话层核心功能**：管理主机进程间的会话，负责**建立、管理和终止会话**，并通过插入同步点（检错点 Checkpoints）实现数据同步与断点续传。
   * **表示层核心功能**：处理两个通信系统中交换信息的**表示方式（语法转换）**，主要包括三大功能：**①数据格式与编码转换**（如 ASCII 与 Unicode 转换，解决不同机器字节序大小端差异）；**②数据加密与解密**；**③数据压缩与解压缩**。
   * **TCP/IP 四层模型**：网络接口层（对应物理层 + 数据链路层）、网际层 IP、运输层（TCP / UDP）、应用层（合并了 OSI 的会话层、表示层和应用层）。

2. **OSI 模型与 TCP/IP 模型在“面向连接 vs 无连接”上的核心差异（高频单选！）**：

| 模型名称 | 网络层（Network Layer）支持的服务 | 运输层（Transport Layer）支持的服务 | 核心设计哲学对比 |
| :--- | :--- | :--- | :--- |
| **ISO/OSI 参考模型** | 同时支持 **无连接** 和 **面向连接** | **仅支持面向连接** 的通信 | 通信可靠性的重担交给网络层或严格面向连接的运输层。 |
| **TCP/IP 模型** | **仅支持无连接** 的服务（IP 数据报） | 同时支持 **无连接（UDP）** 和 **面向连接（TCP）** | **“沙漏模型 / 端到端原则”**：网络核心（IP层）保持极简无连接，复杂的可靠传输与是否建连的选择权完全交给端系统的运输层！ |

#### 补丁 2：物理层数字编码与调制波形全解析（大纲 二(一)3）

1. **数字数据编码为数字信号（基带传输 6 大编码规则与判别特征）**：

| 编码名称 | 电平跳变规则（看图识波形核心依据） | 是否自带时钟同步信号 | 编码效率（波特率与比特率关系） | 典型应用场景 |
| :--- | :--- | :---: | :--- | :--- |
| **不归零制（NRZ）** | 高电平代表 `1`，低电平代表 `0`（或反之），整个码元周期内电平保持不变。 | **否**（遇到连续 `1` 或连续 `0` 时完全无跳变，收发双方极易丢失时钟同步，且存在直流分量） | $100\%$（$B = R$） | 计算机内部近距离含独立时钟线的并行总线 |
| **反向不归零编码（NRZI）** | 信号电平**翻转（跳变）代表 `0`**，电平**保持不变代表 `1`**。 | 连续 `0` 可同步，但连续 `1` 仍无跳变 | $100\%$（$B = R$） | USB 2.0、光纤 FDDI |
| **归零制（RZ）** | 正脉冲代表 `1`，负脉冲代表 `0`，但**每个码元周期的中间时刻电平必须归回到零电平**。 | **是**（但占用了一半归零时间，且共有 $+1, 0, -1$ 三种电平状态） | $50\%$（$B = 2R$） | 早期低速同步信道 |
| **曼彻斯特编码（Manchester）** | 每个码元周期的**正中间时刻必须发生一次电平跳变**：中间**向上跳变代表 `0`、向下跳变代表 `1`**（或反之，依约定而定）。中心的跳变既作时钟信号，又作数据信号！ | **是**（自同步能力极强，无直流分量） | **$50\%$**（每传 $1\text{ bit}$ 需 $2$ 个脉冲码元，**波特率 $B = 2R$**） | **传统 $10\text{ Mbit/s}$ 以太网（10BASE-T）** |
| **差分曼彻斯特编码** | 每个码元周期的**正中间时刻恒有一次跳变（仅作时钟同步）**；表示数据看**每个码元开始边界处是否跳变**：码元**起点处有跳变代表 `0`，起点处无跳变（电平延续上一码元末尾）代表 `1`**！ | **是**（抗干扰性比曼彻斯特更强，且不怕两根导线极性接反） | **$50\%$**（波特率 $B = 2R$） | **IEEE 802.5 令牌环局域网** |
| **4B/5B 编码** | 将每 $4\text{ bit}$ 原始数据查表映射为 $5\text{ bit}$ 编码（从 $2^5=32$ 种组合中精选出 16 种不会出现超过连续 3 个 `0` 的组合），再配合 NRZI 发送。 | **是**（解决了 NRZI 连续 `1` 不跳变问题） | **$80\%$**（波特率 $B = 1.25R$） | **$100\text{ Mbit/s}$ 快速以太网（100BASE-TX）** |

2. **数字数据调制为模拟信号（频带传输 4 大调制方式）**：
   * **调幅（ASK / 2ASK）**：用载波振幅的有无（或大小）表示 `1` 和 `0`。实现最简单，但抗噪声干扰能力最差。
   * **调频（FSK / 2FSK）**：用两种不同的载波频率 $f_1, f_2$ 表示 `1` 和 `0`。抗干扰能力强，但占用频带较宽。
   * **调相（PSK / 2PSK / QPSK）**：用载波初始相位的改变表示数据。分为绝对调相（如 $0^\circ$ 表 `0`、$180^\circ$ 表 `1`）和相对调相（DPSK）。**QPSK（正交相移键控）**采用 4 种相位（$M=4$），每个码元携带 $\log_2 4 = 2\text{ bit}$ 信息。
   * **正交振幅调制（QAM）**：将 **振幅（ASK）和相位（PSK）结合起来同时调制**。若某个星座图有 $m$ 种振幅和 $n$ 种相位，且可组合出 $M$ 个星座点（如 `16-QAM` 有 $M=16$ 个点，`64-QAM` 有 $M=64$ 个点），则每个码元携带 $\log_2 M\text{ bit}$ 信息，数据传输速率 $R = B \log_2 M$。

#### 补丁 3：纠错编码——海明码（Hamming Code）完整原理与手算模板（大纲 三(三)2）

1. **码距（海明距离 $d_{\min}$）与检错/纠错能力定理（必背公式）**：
   * 两个等长码字之间**对应比特位不同的个数**称为两个码字的海明距离；整个编码集中任意两个合法码字海明距离的**最小值**称为该编码的**码距 $d_{\min}$**。
   * **检错能力公式**：为了**检测出 $e$ 个比特**的错码，要求码距满足：
     $$d_{\min} \ge e + 1$$
   * **纠错能力公式**：为了**纠正 $t$ 个比特**的错码，要求码距满足：
     $$d_{\min} \ge 2t + 1$$
   * **同时检错与纠错公式**（检出 $e$ 位错，同时纠正其中 $t$ 位错，且 $e \ge t$）：
     $$d_{\min} \ge e + t + 1$$
   * *推论*：奇偶校验码的码距 $d_{\min} = 2$（只能检出 1 位或奇数位错，不能纠错，$t=0$）；能纠正 1 位错的海明码最小码距为 **$d_{\min} = 2 \times 1 + 1 = 3$**！

2. **海明码四步手算标准算例（考场直接套用）**：
   * **【例题】**：已知 4 位原始数据位为 $D_4 D_3 D_2 D_1 = 1010$（按从低位 $D_1=0, D_2=1, D_3=0, D_4=1$ 排列）。求：(1) 按偶校验构造海明码；(2) 若接收端收到的海明码第 6 位出错变为 `1110110`（位号 $1\sim 7$ 从左到右或从低到高排列），如何定位并纠错？
   * **【第一步：确定校验位位数 $k$】**：
     数据位 $n = 4$，代入**海明不等式**：
     $$2^k \ge n + k + 1$$
     当 $k = 3$ 时，$2^3 = 8 \ge 4 + 3 + 1 = 8$ 成立！故需要 **$k = 3$ 位校验位（$P_1, P_2, P_3$）**，海明码总位数为 $n + k = 4 + 3 = 7$ 位（编号为第 $1 \sim 7$ 位）。
   * **【第二步：安放校验位与数据位的位置】**：
     * **铁律**：校验位 $P_i$ 永远放在位号为 **$2^{i-1}$** 的位置上（即第 **$1, 2, 4, 8, 16 \dots$** 位）；其余位置按顺序填入数据位！

| 海明码位号 $H_j$ | **第 1 位** ($2^0$) | **第 2 位** ($2^1$) | 第 3 位 | **第 4 位** ($2^2$) | 第 5 位 | 第 6 位 | 第 7 位 |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **二进制位号** | `001` | `010` | `011` | `100` | `101` | `110` | `111` |
| **填入符号** | **$P_1$** | **$P_2$** | $D_1$ | **$P_3$** | $D_2$ | $D_3$ | $D_4$ |
| **已知数据数值** | 待求 | 待求 | **`0`** | 待求 | **`1`** | **`0`** | **`1`** |

   * **【第三步：分组异或求校验位 $P_1, P_2, P_3$（偶校验）】**：
     * **分组技巧**：看上表中的“二进制位号”——
       * 凡是二进制位号**第 1 位（最低位 `__1`）为 `1`** 的列（即第 **$1, 3, 5, 7$** 位），归 **$P_1$** 管：
         $$P_1 = H_3 \oplus H_5 \oplus H_7 = D_1 \oplus D_2 \oplus D_4 = 0 \oplus 1 \oplus 1 = \mathbf{0}$$
       * 凡是二进制位号**第 2 位（中间位 `_1_`）为 `1`** 的列（即第 **$2, 3, 6, 7$** 位），归 **$P_2$** 管：
         $$P_2 = H_3 \oplus H_6 \oplus H_7 = D_1 \oplus D_3 \oplus D_4 = 0 \oplus 0 \oplus 1 = \mathbf{1}$$
       * 凡是二进制位号**第 3 位（最高位 `1__`）为 `1`** 的列（即第 **$4, 5, 6, 7$** 位），归 **$P_3$** 管：
         $$P_3 = H_5 \oplus H_6 \oplus H_7 = D_2 \oplus D_3 \oplus D_4 = 1 \oplus 0 \oplus 1 = \mathbf{0}$$
     * 将算出的 $P_1=0, P_2=1, P_3=0$ 填回表中，得到最终发送的 7 位海明码（按 $H_1 \sim H_7$ 顺序）为：**`0 1 0 0 1 0 1`**。
   * **【第四步：接收端计算指错字（校验子 $S_3 S_2 S_1$）定位错位】**：
     * 设在传输中第 6 位（$H_6$）由 `0` 翻转为 `1`，接收端收到的 $H_1 \sim H_7$ 为 `0 1 0 0 1 1 1`。
     * 接收端对三组分别进行异或求指错字 $S_1, S_2, S_3$：
       * $S_1 = P_1 \oplus H_3 \oplus H_5 \oplus H_7 = 0 \oplus 0 \oplus 1 \oplus 1 = \mathbf{0}$
       * $S_2 = P_2 \oplus H_3 \oplus H_6 \oplus H_7 = 1 \oplus 0 \oplus 1 \oplus 1 = \mathbf{1}$
       * $S_3 = P_3 \oplus H_5 \oplus H_6 \oplus H_7 = 0 \oplus 1 \oplus 1 \oplus 1 = \mathbf{1}$
     * 将指错字按高位到低位排列得到二进制数 **$S_3 S_2 S_1 = \mathbf{110_2} = \mathbf{6}$**！
     * 指错字直接指出：**第 6 位（$H_6$）发生了比特翻转**！将该位取反（$1 \rightarrow 0$）即完成自动纠错（若 $S_3 S_2 S_1 = 000$ 则表示无差错）。

#### 补丁 4：三种可靠传输滑动窗口协议深度对比——停等 vs GBN vs SR（大纲 三(四)1~4）

| 比较维度 | 停止-等待协议（Stop-and-Wait） | 后退 N 帧协议（GBN，连续 ARQ） | 选择重传协议（SR，Selective Repeat） |
| :--- | :--- | :--- | :--- |
| **发送窗口大小 $W_T$** | **$W_T = 1$** | **$1 < W_T \le 2^n - 1$**（$n$ 为序号比特数） | **$1 < W_T \le 2^{n-1}$**（通常取 $W_T = W_R = 2^{n-1}$） |
| **接收窗口大小 $W_R$** | **$W_R = 1$** | **$W_R = 1$**（严格只按序接收！） | **$1 < W_R \le 2^{n-1}$**（且必须满足 **$W_T + W_R \le 2^n$**） |
| **接收方收到失序帧的处理** | 直接丢弃重复帧，重发确认 | **直接丢弃所有失序帧！**（即便后面的帧完好到达也不缓存），并重复发送对已按序收到的最后一个帧的**累积确认** | **缓存窗口内的失序帧！** 并对该失序帧单独发送**选择确认（个体确认 ACK）**，等前面缺失的帧补齐后一并按序交付上层 |
| **发送方超时重传策略** | 重传当前唯一未确认的帧 | **后退 N 帧全重传**：一旦某帧超时，不仅重传该帧，还要把该帧之后已经发出去的所有 $N$ 个帧全部重传一遍 | **只重传真正丢失/超时的那一个帧！**（每个已发帧都有独立的超时计时器，或接收方发 `NAK` 显式请求重传指定缺帧） |
| **确认方式** | 逐帧确认 | **累积确认（Cumulative ACK）**（允许捎带确认） | **逐帧个体确认（Individual ACK）**（绝不累积！） |
| **优缺点与适用场景** | 极简，但长时延高带宽下信道利用率极低 | 接收方无需大缓存、实现简单；但**误码率高时会引发大量不必要的回退重传**，浪费带宽 | 避免重复传送已正确到达的帧，**传输效率最高**；但接收方需复杂缓存与排序逻辑，且序号空间利用率为一半 |

* **【为什么 SR 的窗口上限只能取到 $2^{n-1}$（即 $W_T + W_R \le 2^n$）？推导实例】**：
  * 设用 $n = 2\text{ bit}$ 编号（序号为 $0, 1, 2, 3$），则 $2^{n-1} = 2$。
  * 若违规令 $W_T = W_R = 3$（此时 $W_T + W_R = 6 > 4$）：发送方发出帧 `0, 1, 2`，接收方全部收到并缓存，此时接收窗口向前滑动 3 格，新接收窗口变为 **`[3, 0, 1]`**（注意：新接收窗口里已经包含了新一轮的序号 `0` 和 `1`！）。
  * 若接收方发回的 `ACK0, ACK1, ACK2` 全在路上丢失，发送方超时重传旧的帧 `0`，此时接收方的新窗口 `[3, 0, 1]` 正好允许接收序号 `0`，接收方就会把**重传的旧帧 `0` 误当作新一轮的新帧 `0` 缓存收下**！
  * 因此，为保证“旧发送窗口”与“完全滑动后的新接收窗口”没有任何序号重叠，必须满足 **$W_T + W_R \le 2^n$**；在发送窗口与接收窗口取相同最大值时，必有 **$W_{T\max} = W_{R\max} = 2^{n-1}$**！

* **【信道利用率通用计算公式（适用于停等 / GBN / SR）】**：
  设发送 1 个数据帧的发送时延为 $T_D = \frac{L_{\text{数据}}}{R}$，单程传播时延为 $\tau$（往返时间 $\text{RTT} = 2\tau$），确认帧发送时延为 $T_A$（通常忽略 $T_A = 0$），发送窗口大小为 $W_T$ 个帧：
  $$U = \frac{W_T \cdot T_D}{T_D + 2\tau + T_A} \quad (\text{注意：若算出的 } U > 1\text{，则取 } U = 100\%\text{！})$$
  * 若题目要求“使信道利用率达到至少 $X\%$（如 $80\%$），求发送窗口 $W_T$ 至少为多少，以及帧序号至少需要几位比特 $n$”：
    1. 先由 $\frac{W_T \cdot T_D}{T_D + 2\tau} \ge 0.8$ 解出最小整数 $W_T$；
    2. 若为 **GBN 协议**：由 $2^n - 1 \ge W_T \Rightarrow 2^n \ge W_T + 1$ 求出最小比特数 $n$；
    3. 若为 **SR 协议**：由 $2^{n-1} \ge W_T \Rightarrow n - 1 \ge \lceil \log_2 W_T \rceil$ 求出最小比特数 $n$！

#### 补丁 5：轮询访问（令牌传递协议）与广域网 HDLC 协议（大纲 三(五)3、三(七)3）

1. **轮询访问介质访问控制：令牌传递协议（Token Passing，如 IEEE 802.5 令牌环网 / 802.4 令牌总线网）**：
   * **核心原理**：物理拓扑可以是环型或总线型，但所有站点在逻辑上组成一个**逻辑环**。环上只有一个特殊的短控制帧称为**“令牌（Token）”**，沿着逻辑环单向逐站传递。
   * **收发四步曲**：
     1. 网络空闲时，只有空令牌在环上循环流动；
     2. 想要发送数据的站点必须等待捕获经过本站的令牌，将“闲令牌”修改为“忙令牌（数据帧）”，在后面附上数据发出；
     3. 数据帧沿环传遍所有站点，目的站点识别出自己的地址后**复制一份数据帧到缓存，同时将该帧中的响应标志位置为“已收到”**，数据帧继续沿环前进回到发送站；
     4. 发送站收到自己发出的帧后，检查响应位确认对方已收到，将自己发出的帧从环上**回收撤除**，并**重新产生一个新的空令牌**传给下一个站点（规定每拿一次令牌最多只能占有信道一个“令牌持有时间”，防止单站长期霸占）。
   * **核心优缺点（与 CSMA/CD 对比必考）**：
     * **优点**：在重负载（通信量很大）时，**绝对不会发生碰撞冲突**，信道利用率可达 $100\%$，且每个站点获得令牌的最大等待时间是严格确定的（具有实时性保证）；
     * **缺点**：在轻负载（没人发数据）时，站点也必须傻等令牌传到自己手里才能发，引入了不必要的等待延迟；且需维护令牌（防令牌丢失或重复令牌），控制复杂。

2. **广域网高级数据链路控制协议：HDLC 协议 vs PPP 协议对比表（大纲 三(七)2,3）**：

| 比较维度 | HDLC 协议（高级数据链路控制，ISO 制定） | PPP 协议（点对点协议，IETF 制定） |
| :--- | :--- | :--- |
| **面向单位** | **面向比特（Bit-oriented）**（数据长度不必是整字节） | **面向字节（Byte-oriented）**（所有帧长均为整字节） |
| **帧定界标志** | 首尾均为 **`01111110`（`0x7E`）** | 首尾均为 **`01111110`（`0x7E`）** |
| **透明传输方法** | 仅采用 **零比特填充法**（发送端逢连续 5 个 `1` 后自动插入 1 个 `0`） | 异步链路用 **字节填充法（`7D` 转义）**；同步 SONET 链路用 **零比特填充法** |
| **是否提供可靠传输** | **提供可靠传输！**（使用帧编号、确认和重传机制，有滑动窗口） | **不提供可靠传输！**（无序号、无确认、无重传，错帧直接丢弃） |
| **适用协议与链路** | 仅支持点对点/多点链路，不直接携带网络层协议类型字段 | 专为点对点全双工链路设计，通过 **LCP（链路控制协议）** 建链、**NCP（网络控制协议）** 支持多种网络层协议 |
| **HDLC 三种帧类型**<br>（由控制字段前1~2位区分） | **①信息帧（I帧，第1位为 `0`）**：传送有效用户数据，并携带发送序号 $N(S)$ 和捎带确认接收序号 $N(R)$；<br>**②监控帧（S帧，前2位为 `10`）**：用于差错控制和流量控制（如接收就绪 RR、拒绝 REJ、接收未就绪 RNR、选择拒绝 SREJ），不带信息字段；<br>**③无编号帧（U帧，前2位为 `11`）**：提供对链路的建立、拆除和多种控制功能。 | 分为 LCP 帧、NCP 帧和封装的 IP 数据报帧（由 2 字节“协议字段”区分：`0x0021` 为 IP 数据报，`0xC021` 为 LCP，`0x8021` 为 NCP）。 |

#### 补丁 6：网络层拥塞控制与路由器硬件体系结构（大纲 四(一)3、四(七)1）

1. **网络层拥塞控制（开环控制 vs 闭环控制 vs 主动队列管理 RED）**：
   * **拥塞原因**：对网络中某一资源（链路带宽、路由器缓存、处理机时间）的需求超过了该资源所能提供的可用部分，导致网络吞吐量随负载增加反而急剧下降，甚至跌为 $0$（称为**死锁 Deadlock**）。
   * **两类控制方法**：
     * **①开环控制（预防）**：在设计网络时事先将可能导致拥塞的因素考虑周到，一旦系统运行起来就不再中途更改。
     * **②闭环控制（基于反馈环路动态调节）**：监测网络系统何时何地发生拥塞 $\rightarrow$ 将拥塞信息传给相关站点 $\rightarrow$ 调整系统操作以消除拥塞。
   * **路由器主动队列管理 AQM 与随机早期检测 RED（Random Early Detection）**：
     * 传统路由器的“尾部丢弃（Tail-drop）”策略会等队列彻底占满才一刀切丢弃后续所有包，导致多条 TCP 连接同时超时进入慢开始，引发**“全局同步（Global Synchronization）”**现象，使网络流量忽大忽小剧烈震荡。
     * **RED（随机早期检测）**：路由器维护两个队列长度门限 $TH_{\min}$（最小门限）和 $TH_{\max}$（最大门限）：
       1. 当平均队列长度 $< TH_{\min}$ 时：不丢弃任何分组，正常入队；
       2. 当平均队列长度 $> TH_{\max}$ 时：丢弃所有新到达的分组；
       3. 当平均队列长度介于 **$[TH_{\min},\ TH_{\max}]$ 之间**时：按照线性计算出的**概率 $p$ 随机丢弃**新到达的分组，从而使个别 TCP 连接提前感知到轻微拥塞而个别减小拥塞窗口，**彻底避免了全网 TCP 的全局同步现象**！

2. **路由器的组成结构与三种交换结构（大纲 四(七)1 高频单选！）**：
   * **两大核心职能模块**：
     * **①路由选择部分（控制层面 / 控制部分）**：核心是**路由选择处理机**，负责运行 RIP、OSPF、BGP 等路由协议，与其他路由器交换路由信息以生成和更新**路由表**，再由路由表导出供硬件快速查找的**转发表（FIB）**。此过程用软件实现，速度较慢（毫秒/秒级）。
     * **②分组转发部分（数据层面）**：由三部分组成——**输入端口、交换结构（Switching Fabric）、输出端口**。根据转发表将输入端口收到的分组高速搬运到对应的输出端口。此过程用硬件（ASIC芯片）实现，速度极快（纳秒级）。
   * **输入/输出端口的三层处理结构**：输入端口依次经过“物理层比特接收 $\rightarrow$ 数据链路层拆帧剥去 MAC 首尾 $\rightarrow$ 网络层查转发表并排队进入交换结构”（输出端口顺序完全相反）。
   * **交换结构的三种实现方式（从慢到快）**：
     1. **通过存储器进行交换**：第一代路由器，由 CPU（路由选择处理机）直接控制，把分组从输入端口复制到存储器，再从存储器复制到输出端口。每转发一个分组需经过两次系统总线，速度极慢。
     2. **通过总线进行交换**：输入端口通过一条共享的高速内部背板总线直接把分组传到输出端口，无需 CPU 干预；但同一时刻总线上只能传一个分组，总线带宽成为瓶颈。
     3. **通过纵横交换结构（Crossbar Switch / 互连网络）进行交换**：由 $2N$ 条水平和垂直交叉的总线网格组成。只要多个输入端口去往的是**不同的输出端口**，就可以**多对端口并行同时转发分组**，无阻塞、吞吐率最高！
   * **队头阻塞（Head-of-Line Blocking, HOL）**：在输入端口队列中，排在队头的分组因为它的目标输出端口正忙（发生冲突）而不得不等待，导致排在它后面的、本来要去往**其他空闲输出端口**的分组也被死死堵在输入队列里无法前进的现象。

#### 补丁 7：链路状态路由算法——OSPF 与 Dijkstra 最短路径算法手算推演模板（大纲 四(二)3、四(五)4）

1. **OSPF 协议核心工作机制（五种分组与区域划分）**：
   * **链路状态构建**：每个路由器通过**洪泛法（Flooding，收到新链路状态就从除进入接口外的所有接口转发，并用确认机制保证可靠洪泛）**向本自治系统（AS）内所有路由器发送“本路由器跟哪些邻居相连、以及该链路的度量代价是多少”。最终全网每个路由器都能建立起一个**全网完全一致的链路状态数据库（LSDB，即全网完整拓扑图）**，然后各自以自己为根运行 **Dijkstra 最短路径算法**。
   * **OSPF 五种分组类型**：**①问候分组（Hello，每10秒发一次，发现和维护邻居可达性）**；**②数据库描述分组（DD，交换数据库摘要目录）**；**③链路状态请求分组（LSR，请求自己缺少的详细记录）**；**④链路状态更新分组（LSU，洪泛详细链路状态，最核心！）**；**⑤链路状态确认分组（LSAck，对 LSU 进行确认）**。
   * **OSPF 区域（Area）两级层次结构**：为使 OSPF 能用于规模很大的自治系统，将 AS 划分为若干个更小的**区域（Area，用 32 位点分十进制标识）**。洪泛仅限制在单个区域内部！其中标识符为 `0.0.0.0`（区域 0）的称为**主干区域（Backbone Area）**，用来连通其他所有下层区域。

2. **Dijkstra 最短路径算法逐轮手算填表模板（大题必会！）**：
   * **【标准例题】**：给定包含 6 个路由器节点 $A, B, C, D, E, F$ 的无向带权网络拓扑图，各边代价为：
     $$(A,B)=2,\ (A,C)=5,\ (A,D)=1,\ (B,C)=3,\ (B,D)=2,\ (C,D)=3,\ (C,E)=1,\ (C,F)=5,\ (D,E)=1,\ (E,F)=2$$
     试以路由器 **$A$** 为源点，使用 Dijkstra 算法按步骤填表求出 $A$ 到其余所有节点的最短路径及距离，并写出路由器 $A$ 的最终路由表（含下一跳）。
   * **【Dijkstra 逐轮迭代计算表（考场标准格式：$D(v)$ 为当前最短距离，$p(v)$ 为前驱节点）】**：

| 步骤 Step | 已确定最短路径的节点集合 $N'$ | $D(B), p(B)$ | $D(C), p(C)$ | $D(D), p(D)$ | $D(E), p(E)$ | $D(F), p(F)$ | 本步选入 $N'$ 的最小距离节点 |
| :---: | :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **初始 0** | $\{A\}$ | $2, A$ | $5, A$ | **$1, A$** | $\infty$ | $\infty$ | 选最小者 **$D$**（距离为 $1$） |
| **第 1 步** | $\{A, D\}$ | **$2, A$** | $4, D$ | 已确定 | $2, D$ | $\infty$ | 选最小者 **$B$**（或 $E$，距离为 $2$） |
| **第 2 步** | $\{A, D, B\}$ | 已确定 | $4, D$ | 已确定 | **$2, D$** | $\infty$ | 选最小者 **$E$**（距离为 $2$） |
| **第 3 步** | $\{A, D, B, E\}$ | 已确定 | **$3, E$** | 已确定 | 已确定 | $4, E$ | 选最小者 **$C$**（经 $E$ 更新为 $2+1=3$） |
| **第 4 步** | $\{A, D, B, E, C\}$ | 已确定 | 已确定 | 已确定 | 已确定 | **$4, E$** | 选最小者 **$F$**（距离为 $4$） |
| **第 5 步** | $\{A, D, B, E, C, F\}$ | $2, A$ | $3, E$ | $1, A$ | $2, D$ | $4, E$ | 全部节点计算完毕！ |

   * **【由前驱节点回溯导出路由器 $A$ 的最终路由表】**：
     * 到 $B$：路径 $A \rightarrow B$（代价 $2$），**下一跳为 $B$**；
     * 到 $D$：路径 $A \rightarrow D$（代价 $1$），**下一跳为 $D$**；
     * 到 $E$：路径 $A \rightarrow D \rightarrow E$（代价 $2$），**下一跳为 $D$**；
     * 到 $C$：路径 $A \rightarrow D \rightarrow E \rightarrow C$（代价 $3$），**下一跳为 $D$**；
     * 到 $F$：路径 $A \rightarrow D \rightarrow E \rightarrow F$（代价 $4$），**下一跳为 $D$**。

#### 补丁 8：IPv4 与 IPv6 首部完整字节图谱及十六进制拆解实战（大纲 四(三)1、四(四)1）

1. **IPv4 数据报固定 20 字节首部完整字段表（每行 4 字节 = 32 bit）**：

| 行号（每行32位） | 字段名称与所占位数 | 核心作用、单位量纲（极易考单选坑点！）与常见取值 |
| :--- | :--- | :--- |
| **第 1 行**<br>（字节 $0 \sim 3$） | **版本（4位）** + **首部长度 IHL（4位）** + **区分服务 TOS/DS（8位）** + **总长度（16位）** | • **版本**：IPv4 固定为 `4`（二进制 `0100`）。<br>• **首部长度（4位）**：**单位是 4 字节（32位字）！** 最小值 `5`（`0101`）代表固定首部 $5 \times 4 = 20\text{ B}$；最大值 `15`（`1111`）代表最大首部 $15 \times 4 = 60\text{ B}$。<br>• **总长度（16位）**：**单位是 1 字节！** 指首部与数据之和的长度，最大为 $2^{16}-1 = 65535\text{ B}$。 |
| **第 2 行**<br>（字节 $4 \sim 7$） | **标识（16位）** + **标志（3位：`0 | DF | MF`）** + **片偏移（13位）** | • **标识（16位）**：计数器，同一数据报切出的所有分片具有完全相同的“标识”值，用于终点重组。<br>• **标志（3位）**：最高位恒为 `0`；中间位 **`DF`（Don't Fragment）**：`DF=1` 禁止分片，`DF=0` 允许分片；最低位 **`MF`（More Fragments）**：`MF=1` 表示后面还有分片，`MF=0` 表示这是最后一片（或未分片）。<br>• **片偏移（13位）**：**单位是 8 字节！** 表示较长分组在分片后，某片在原分组数据中的相对起始位置除以 $8$。 |
| **第 3 行**<br>（字节 $8 \sim 11$） | **生存时间 TTL（8位）** + **协议（8位）** + **首部检验和（16位）** | • **TTL（8位）**：数据报在网中可通过的**路由器最大跳数**，每经过一个路由器减 1，减至 0 则丢弃并发回 ICMP 超时报文（防止路由环路无限兜圈）。<br>• **协议（8位）**：指出数据部分应交给哪个上层协议——必记数值：**`ICMP = 1`**，**`IGMP = 2`**，**`TCP = 6`**，**`UDP = 17`**，**`IPv6封装 = 41`**，**`OSPF = 89`**。<br>• **首部检验和（16位）**：仅检验 IP 首部，每跳重算。 |
| **第 4 行**<br>（字节 $12 \sim 15$） | **源 IP 地址（32位，4字节）** | 发送端主机的 IPv4 地址（無 NAT 时全程不变）。 |
| **第 5 行**<br>（字节 $16 \sim 19$） | **目的 IP 地址（32位，4字节）** | 接收端主机的 IPv4 地址（无 NAT 时全程不变）。 |

   * **【IPv4 首部三大字段单位口诀（必背）】**：“**总长度按 1 字节算，首部长度按 4 字节算，片偏移按 8 字节算（一四八原则）！**”

2. **十六进制 IPv4 首部拆解实战算例**：
   * **【例题】**：路由器收到一个 IPv4 分组，其首部前 20 字节的十六进制表示为：`45 00 00 3C 1C 46 40 00 40 06 B8 61 C0 A8 01 01 C0 A8 01 02`。试拆解其核心字段。
   * **【秒拆解析】**：
     * `45`：版本 $= 4$（IPv4），首部长度 $= 5 \times 4\text{ B} = \mathbf{20\text{ B}}$（无选项）；
     * `00`：区分服务 $= 0$；
     * `00 3C`：总长度 $= 3 \times 16 + 12 = \mathbf{60\text{ B}}$（故数据载荷长度为 $60 - 20 = 40\text{ B}$）；
     * `1C 46`：标识 $= \text{0x1C46}$；
     * `40 00`：化成 16 位二进制为 `010 00000 00000000`，前 3 位标志为 `010`（即 **`DF = 1` 不允许分片，`MF = 0`**），后 13 位片偏移 $= \mathbf{0}$；
     * `40`：生存时间 $\text{TTL} = 4 \times 16 = \mathbf{64}$ 跳；
     * `06`：协议字段 $= 6$，代表上层载荷是 **`TCP` 报文段**！
     * `B8 61`：首部检验和 $= \text{0xB861}$；
     * `C0 A8 01 01`：源 IP 地址（$\text{C0}=192,\ \text{A8}=168$）$= \mathbf{192.168.1.1}$；
     * `C0 A8 01 02`：目的 IP 地址 $= \mathbf{192.168.1.2}$。

3. **IPv6 基本首部与地址分类（大纲 四(四)1,2）**：
   * **基本首部固定 40 字节（共 8 个字段）**：版本（4位，值为6）、通信量类（8位）、流标号（20位，用于实时音视频流识别）、有效载荷长度（16位，指除40B基本首部以外的扩展首部+数据长度）、下一个首部（8位）、跳数限制（8位，相当于TTL）、源地址（128位，16B）、目的地址（128位，16B）。
   * **IPv6 三种基本目的地址类型（注意：IPv6 彻底取消了广播地址！）**：
     1. **单播（Unicast）**：点对点通信；
     2. **多播（Multicast）**：一点对多点通信（完全替代了 IPv4 的广播功能，前缀固定为 `FF00::/8`）；
     3. **任播（Anycast，IPv6 新增！）**：终点是一组计算机，但数据报只交付给这一组计算机中**距离最近的那一台**（常用于根 DNS 服务器镜像集群寻址）。

#### 补丁 9：IP 组播概念、IGMP 与组播 MAC 地址映射完整算例（大纲 四(六)1,2）

1. **IP 组播（多播 Multicast）基本原理与两大协议**：
   * 当源主机要向互联网上的大量接收者同时发送相同的视频/直播流时，采用**组播**可使分组在每条链路上只传送 1 份，仅在路径分叉处的组播路由器才复制转发，极大节省网络带宽。
   * **网际组管理协议 IGMP（Internet Group Management Protocol，直接封装在 IP 数据报中，协议号 2）**：运行在**本地局域网上的主机与直连的多播路由器之间**，用来让本地多播路由器知道本局域网上是否有主机加入或退出了某个多播组（注意：IGMP 仅工作在最后一跳局域网，不负责跨网路由；跨网传输需配合多播路由选择协议）。

2. **D 类 IP 组播地址映射为以太网硬件多播 MAC 地址（必考计算！）**：
   * **IPv4 D 类组播地址范围**：前 4 位固定为 **`1110`**，点分十进制范围为 **`224.0.0.0` $\sim$ `239.255.255.255`**（后 28 位为多播组标识符）。

   * **【手算转换标准算例】**：
     * **题目**：将 IP 组播地址 `224.215.145.230` 转换为对应的以太网多播 MAC 地址（十六进制）。
     * **秒算步骤**：
       1. 前 3 个字节（高 24 位）直接写死为：**`01-00-5E`**；
       2. 看 IP 地址的**第 2 个字节** `215`：将其对 $128$ 取余（即抹掉第 2 字节的最高位，因为只取后 23 位，第 2 字节只保留低 7 位！）：
          $$215 \pmod{128} = 215 - 128 = \mathbf{87} = 5 \times 16 + 7 = \mathbf{\text{0x57}}$$
       3. 看 IP 地址的**第 3 个字节** `145`（全保留）：$145 = 9 \times 16 + 1 = \mathbf{\text{0x91}}$；
       4. 看 IP 地址的**第 4 个字节** `230`（全保留）：$230 = 14 \times 16 + 6 = \mathbf{\text{0xE6}}$；
       5. 拼合即得最终以太网多播 MAC 地址：**`01-00-5E-57-91-E6`**！

| 行号（每行32位） | 字段名称与所占位数 | 核心作用、单位量纲与 6 大标志位含义（必背！） |
| :--- | :--- | :--- |
| **第 1 行**<br>（字节 $0 \sim 3$） | **源端口（16位，2B）** + **目的端口（16位，2B）** | 标识发送方和接收方的应用进程（加上源/目的 IP 构成唯一确定 TCP 连接的四元组）。 |

| **第 3 行**<br>（字节 $8 \sim 11$） | **确认号 `ack`（32位，4B）** | **期望收到对方下一个报文段的第一个数据字节的序号**！若确认号为 $N$，则表明到序号 $N-1$ 为止的所有数据均已正确收到（累积确认）。 |

| **第 5 行**<br>（字节 $16 \sim 19$） | **检验和（16位，2B）** + **紧急指针（16位，2B）** | • **检验和**：加上 12 字节伪首部后，同时检验 TCP 首部和 TCP 数据。<br>• **紧急指针**：仅在 `URG=1` 时有效，指出本报文段中紧急数据的字节数。 |

2. **十六进制 TCP 首部拆解实战算例**：

#### 补丁 11：HTTP 协议报文结构、方法、状态码、Cookie 与 Web 缓存（大纲 六(六)2）

1. **HTTP 两类报文结构与核心特征**：
   * **无状态性（Stateless）**：HTTP 服务器本身**不记录**某客户此前是否访问过自己（这简化了服务器设计以支持高并发，但为了识别用户身份与购物车状态，引入了 **Cookie** 机制）。
   * **面向文本（ASCII 码）**：无论是 HTTP 请求报文还是响应报文，均由三部分组成——**①开始行**（请求行 `方法 URL 版本 CRLF` / 状态行 `版本 状态码 短语 CRLF`）；**②首部行**（若干行 `首部字段名: 值 CRLF`，最后以一个**单独的空行 `CRLF`** 结束首部）；**③实体主体**（请求中通常为空，`POST` 时存放表单数据；响应中存放网页 HTML/图片内容）。

2. **HTTP 常用请求方法与五类状态码速查表（单选高频！）**：

| HTTP 请求方法 | 作用说明 | 状态码大类与必背代表值 | 状态码含义说明 |
| :--- | :--- | :--- | :--- |
| **`GET`** | 请求读取由 URL 所标志的信息（最常用） | **`1xx`（信息通知）** | 收到请求，正在处理（如 `100 Continue`） |
| **`HEAD`** | 请求读取由 URL 所标志的信息的**首部**（服务器响应中**不含实体主体**，常用于测试链接有效性或查看文档修改时间） | **`2xx`（成功）** | • **`200 OK`**：请求成功，信息在返回的响应报文中。<br>• **`202 Accepted`**：已接受请求但尚未处理完成。 |
| **`POST`** | 给服务器添加信息（如向服务器提交网页表单、发表评论或上传数据，数据放在实体主体中） | **`3xx`（重定向）** | • **`301 Moved Permanently`**：永久移动（新 URL 在响应首部 `Location` 中给出）。<br>• **`302 Found`**：临时重定向。<br>• **`304 Not Modified`**：**未修改！**（配合条件 GET 缓存使用，响应中不含实体主体）。 |
| **`PUT`** | 在指明的 URL 下存储一个文档 | **`4xx`（客户差错）** | • **`400 Bad Request`**：客户端请求报文有语法错误。<br>• **`403 Forbidden`**：服务器禁止访问。<br>• **`404 Not Found`**：请求的文档在服务器上不存在。 |
| **`DELETE`** | 删除指明的 URL 所标志的资源 | **`5xx`（服务器差错）** | • **`500 Internal Server Error`**：服务器内部错误。<br>• **`503 Service Unavailable`**：服务器暂时过载无法服务。 |

3. **Cookie 维持用户状态的“四步工作机制”**：
   1. 用户首次用浏览器访问某网站时，服务器在后台数据库中为该用户生成一个**唯一的识别码（Cookie ID）**，并以此作为索引建立该用户的后台记录项；
   2. 服务器在发回给浏览器的 HTTP 响应报文中添加一行首部：**`Set-Cookie: <识别码>`**；
   3. 浏览器收到响应后，将该识别码追加保存在本地电脑的特定 Cookie 文件中；
   4. 当用户后续再次浏览该网站的任何页面时，浏览器会自动在发出的每一个 HTTP 请求报文中附带一行首部：**`Cookie: <识别码>`**，服务器据此立刻查出该用户的登录身份与历史购物车状态！

4. **代理服务器（Web 缓存 Proxy Cache）与“条件 GET（Conditional GET）”机制**：
   * **代理服务器作用**：部署在校园网/企业网出口，暂存最近请求过的万维网对象。若校园网内其他主机请求同一对象，直接从本地代理服务器高速返回，**既大幅缩短了用户访问延迟，又显著减少了校园网出口链路的通信量**。
   * **怎么保证代理缓存里的网页不是过期的旧网页？（条件 GET 流程）**：
     1. 代理服务器缓存某对象时，一并记录下当时响应首部中的最后修改时间 **`Last-Modified: <日期时间>`**；
     2. 当需要核实该缓存对象是否过期时，代理服务器向原服务器发送一个包含 **`If-Modified-Since: <原缓存日期时间>`** 首部行的 **条件 GET 请求报文**；
     3. 若原服务器检查发现该网页自该日期以来**没有被修改过**，原服务器就只发回一个极短的 **`304 Not Modified` 响应报文（里面不携带任何网页实体数据！）**，代理服务器便可放心地把本地缓存的网页交给用户；只有当网页确实被修改过时，原服务器才返回 `200 OK` 并重传最新网页全文。
