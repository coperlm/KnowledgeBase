## 一、 域名系统 DNS 的顶层架构（共 2 题，对应官方大纲六(二)1,2）

### 1. `6-01` 互联网的域名结构是怎样的？它与目前的电话网的号码结构有何异同之处？
* **【说人话】**：域名（如 `www.seu.edu.cn`）和电话号码（如 `+86-25-8379xxxx`）都是“从大范围到小范围的树状层次结构”。但你看书写顺序正好反过来：电话号码是**从左到右越来越小**（先写国家码 `+86`，再写南京区号 `25`，最后写校内分机号）；而域名是**从右到左越来越小**（最右边 `.cn` 是最大的顶级域，往左 `.edu` 是二级域，`seu` 是三级域，最左边 `www` 是具体的一台主机）！更核心的区别是：电话号码跟你的物理地理位置和电话局交换机死死绑在一起；而域名只是个逻辑名字，哪怕东南大学把服务器从南京搬到北京机房，域名 `www.seu.edu.cn` 连一个字母都不用改！
* **【严谨考场结论】**：
  * **互联网域名结构**：采用**层次树状结构的命名方法**。任何一个连接在互联网上的主机或路由器，都有一个唯一的层次结构的名字即域名（Domain Name）。域名由若干个分量组成，各分量之间用点（`.`）隔开，**级别最低的域名写在最左边，而级别最高的顶级域名写在最右边**（`... .三级域名.二级域名.顶级域名`）。域名树每一层的节点标号不超过 63 个字符，完整域名总长度不超过 255 个字符，且不区分大小写。
  * **与电话网号码结构的异同**：
    * **相同点**：两者都采用**层次树状结构**来保证全球命名/编号的唯一性，便于分级管理与查找。
    * **不同点**：**①书写方向相反**：电话号码最高级别（国家号、区号）在最左边，最低级别在最右边；域名最高级别（顶级域）在最右边，最低级别在最左边。**②与地理位置/物理拓扑的关系不同**：电话号码与地理位置及物理交换机严格绑定（跨省搬迁必须换区号）；而**域名是逻辑概念，与主机所在的物理地理位置、所属 IP 子网完全无关**（服务器物理迁移或更换 IP 地址后，只需修改 DNS 记录，域名本身完全不变）。

### 2. `6-02` 域名系统的主要功能是什么？域名系统中的本地域名服务器、根域名服务器、顶级域名服务器以及权限域名服务器有何区别？（`2025-大2` 核心背景）
* **【说人话】**：DNS 就是互联网的“全球分布式查号台”，把人类好记的域名翻译成电脑只认的 32位 IP 地址。为什么不搞一台超级计算机存下全世界所有网站的 IP？因为一旦这台机器断电，全球断网！所以全球拆成了四级查号员：
  * **本地域名服务器（Local DNS）**：你们学校信息中心机房里的那台 DNS（也叫默认 DNS）。你电脑要查任何网址，第一步永远是先找它！
  * **根域名服务器（Root DNS）**：全球最高法院（共13套逻辑根，编号 `a.root-servers.net` 到 `m`）。它不存具体网站 IP，只存 `.com`、`.cn` 等所有**顶级域名服务器**的 IP。
  * **顶级域名服务器（TLD DNS）**：掌管所有以 `.cn`、`.com`、`.edu` 结尾的二级域名归谁管（比如告诉本地 DNS：“要查 `seu.edu.cn`，请去找东南大学自己的权限服务器”）。
  * **权限域名服务器（Authoritative DNS）**：东南大学自己机房里管 `seu.edu.cn` 这个区的服务器，只有它手里攥着 `www.seu.edu.cn` 最终的真实 IP 地址！
* **【严谨考场结论】**：
  * **DNS 主要功能**：将用户使用的易于记忆的主机**域名转换为 IP 地址**（采用客户/服务器方式，分布式数据库系统，主要使用 **UDP 端口 53**）。
  * **四类域名服务器职责区别**：
    1. **根域名服务器（Root Name Server）**：最高层次的域名服务器，也是最重要的域名服务器。所有的根域名服务器都知道所有的**顶级域名服务器**的域名和 IP 地址。不管是哪一个本地域名服务器，若自己无法解析，首先求助的就是根域名服务器。
    2. **顶级域名服务器（TLD Server）**：负责管理在该顶级域名服务器注册的所有**二级域名**。收到 DNS 查询请求时，就给出相应的回答（可能是最后的结果，也可能是下一步应当找的权限域名服务器的 IP 地址）。
    3. **权限域名服务器（Authoritative Name Server）**：负责一个**“区（Zone）”**的域名服务器，用来保存该区中所有主机的域名到 IP 地址的最终权威映射记录。
    4. **本地域名服务器（Local Name Server / 默认域名服务器）**：并不属于上述三级域名树层次结构，但对域名系统极为重要。当一台主机发出 DNS 查询请求时，这个查询请求报文就**首先发送给该主机的本地域名服务器**（通常由本地 ISP 或大学校园网提供，与主机处于同一局域网或较近网络，由它代表客户端向根、顶级、权限服务器发起迭代查询并缓存结果）。

## 二、 万维网 WWW 与 HTTP 底层运转机制（共 5 题，对应官方大纲六(六)）

### 3. `6-08` 解释以下名词，各英文缩写词的原文是什么？WWW、URL、HTTP、HTML、CGI、浏览器、超文本、超媒体、超链、页面、活动文档、搜索引擎。
* **【说人话（重点抓 WWW 四大基石题眼）】**：万维网（WWW）其实只回答了四个问题：
  1. **怎么唯一标记网上的一个资源在哪里？** $\rightarrow$ 用 **URL（统一资源定位符）**；
  2. **客户和服务器怎么对话把资源要过来？** $\rightarrow$ 用 **HTTP（超文本传送协议）**；
  3. **拿过来的文档怎么排版显示在屏幕上？** $\rightarrow$ 用 **HTML（超文本标记语言）**；
  4. **用什么软件点链接看页面？** $\rightarrow$ 用 **浏览器（Browser）**。
* **【严谨考场结论】**：
  * **WWW（World Wide Web，万维网）**：是一个大规模的、联机式的信息储藏所，用链接的方法能非常方便地从互联网上的一个站点访问另一个站点。
  * **URL（Uniform Resource Locator，统一资源定位符）**：用来唯一标识万维网上的各种文档和资源的位置。一般格式为：`<协议>://<主机>:<端口>/<路径>`（其中协议和主机域名**不区分大小写**，但 `<路径>` **有时区分大小写**；HTTP 默认端口为 **80**）。
  * **HTTP（HyperText Transfer Protocol，超文本传送协议）**：定义了浏览器（万维网客户进程）怎样向万维网服务器请求万维网文档，以及服务器怎样把文档传送给浏览器的应用层协议（面向事务、无状态，基于 TCP）。
  * **HTML（HyperText Markup Language，超文本标记语言）**：一种制作万维网页面的标准语言，消除了不同计算机之间信息交流的障碍，控制页面排版结构。
  * **超文本（Hypertext）与超媒体（Hypermedia）**：包含指向其他文档的**超链（Hyperlink）**的文本叫超文本；若不仅包含文本，还包含图形、音频、视频等多媒体信息，则称为超媒体。
  * **CGI（Common Gateway Interface，通用网关接口）**：是一种标准，定义了动态文档应如何创建，输入数据应如何提供给服务器上的应用程序，以及输出结果应如何使用。
  * **静态文档 vs 动态文档 vs 活动文档**：**静态文档**内容在创作完毕后就固定存于服务器磁盘中；**动态文档**是在浏览器访问时才由万维网服务器现场运行一个应用程序动态生成的；**活动文档（Active Document）**是服务器把一段程序代码（如 Java Applet 或 JavaScript 脚本）直接发给浏览器，**在浏览器本地端持续运行**并直接与用户交互、动态改变屏幕显示。

### 4. `6-09` 假定一个超链从一个万维网文档链接到另一个万维网文档时，由于万维网文档上出现了差错而使得超链指向一个无效的计算机名字。这时浏览器将向用户报告什么？
* **【说人话】**：注意审题！题目说的是超链里的**“计算机名字（即主机域名，如 `www.seu_error.edu.cn`）是无效的”**，而不是网页路径 `/abc.html` 不存在！既然连域名都是瞎编的，你的浏览器第一步去问 DNS 查号台时，DNS 就会两手一摊说“查无此人”。连服务器 IP 都拿不到，你根本连 TCP 握手和 HTTP 请求都发不出去，怎么可能收到 HTTP 的 `404 Not Found` 呢？
* **【严谨考场结论】**：由于超链中的**主机域名无效**，浏览器在第一步调用 **DNS 域名解析**时就会失败（收到 DNS 返回的“域名不存在”响应），根本无法获得目标服务器的 IP 地址，更无法建立 TCP 连接和发送 HTTP 请求。因此，浏览器会直接向用户报告 **“找不到服务器”或“无法解析服务器的 DNS 地址（Server Not Found / DNS_PROBE_FINISHED_NXDOMAIN）”**（注意：**绝不是报告 HTTP `404 Not Found`！** 只有当域名解析成功、建立 TCP 连接并发送 HTTP 请求后，服务器上找不到对应的 `<路径>` 文件时，服务器才会返回 `404 Not Found`）。

### 5. `6-10` 假定要从已知的 URL 获得一个万维网文档。若该万维网服务器的 IP 地址开始时并不知道。试问：除 HTTP 外，还需要什么应用层协议和运输层协议？（`2025-大2` 核心串联）
* **【严谨考场结论】**：
  1. **还需要的应用层协议**：**DNS（域名系统）**——用于将 URL 中的万维网服务器域名解析为 IP 地址。
  2. **需要的运输层协议**：
     * **UDP（用户数据报协议）**：供 **DNS** 查询和响应报文使用（服务器端口 53）；
     * **TCP（传输控制协议）**：供 **HTTP** 建立可靠连接、发送请求报文和接收万维网文档响应报文使用（服务器端口 80）。

### 6. `6-12` 什么是动态文档？试举出万维网使用动态文档的一些例子。
* **【严谨考场结论】**：**动态文档（Dynamic Document）**是指文档的内容不是预先做好存放在服务器磁盘上的，而是在**浏览器访问万维网服务器时，由服务器当场运行一个后台应用程序（通过 CGI、PHP、JSP 等）动态生成的**。
  * **典型例子**：在铁路 12306 网站查询余票、在搜索引擎输入关键词查询结果、查询教务系统个人成绩单、电子商务网站购物车结算页面等（每次查询返回的内容都随数据库实时状态和用户输入参数而变）。

### 7. `6-13` 浏览器同时打开多个 TCP 连接进行浏览的优缺点如何？请说明理由。
* **【说人话】**：一个网页上有 10 张图，如果浏览器一口气并行开 10 条 TCP 连接去抢带宽，对你个人来说网页打开确实快了；但如果全校一万个学生每人打开一个网页都瞬间建 10 条连接，一方面服务器内存和端口瞬间被撑爆，另一方面你在网络里占了 10 条车道，把别人正常只开 1 条车道的流量全挤死了（不公平抢占带宽）！
* **【严谨考场结论】**：
  * **优点**：**缩短了用户的网页加载响应时间**。多个内嵌对象（图片、脚本）可以并行请求和传输，避免了串行排队等待，同时在网络拥塞时，拥有 $N$ 条并行 TCP 连接的浏览器能比只用 $1$ 条连接的应用抢占到近似 $N$ 倍的链路带宽。
  * **缺点**：**①加重了万维网服务器的负担**（服务器需同时维护成倍增加的 TCP 连接状态与缓存，消耗大量内存与 CPU）；**②加剧了互联网的拥塞且对其他应用不公平**（多条连接同时进行慢开始会瞬间向网络注入大量突发分组，且不公平地挤占了其他单连接通信的带宽）；**③额外消耗了大量三次握手与四次挥手的控制报文开销**。

## 三、 电子邮件系统架构、格式与 Webmail 协议组合（共 6 题，对应官方大纲六(五)1,2,3）

### 8. `6-20` 试述电子邮件的最主要的组成部件。用户代理 UA 的作用是什么？没有 UA 行不行？（官方大纲六(五)1明确列出！）
* **【严谨考场结论】**：
  * **电子邮件系统的三个最主要组成部件**：**①用户代理 UA（User Agent）**、**②邮件服务器（Mail Server）**、**③电子邮件所需的协议（包括邮件发送协议如 SMTP，和邮件读取协议如 POP3 / IMAP）**。
  * **用户代理 UA 的作用**：用户代理就是**用户与电子邮件系统的接口**（实质上是运行在用户电脑或手机上的电子邮件客户端软件，如 Foxmail、Outlook）。它向用户提供友好的图形界面，具备四大基本功能：**①撰写**（帮助用户编写信件）；**②显示**（在屏幕上展示收到的来信）；**③处理**（转发、回复、分类保存、删除邮件）；**④通信**（调用发送协议向邮件服务器发信，调用读取协议从邮件服务器收信）。
  * **没有 UA 行不行**：**不行**。如果没有用户代理 UA，普通用户就必须自己直接按照极其繁琐的 SMTP、MIME 和 POP3 协议命令格式及 ASCII 编码规则去手工敲命令与邮件服务器交互，这在实际使用中是根本无法操作的。

### 9. `6-21` 电子邮件的信封和内容在邮件的传送过程中起什么作用？和用户的关系如何？（官方大纲六(五)2明确列出！）
* **【说人话】**：就像寄纸质信一样——邮局分拣员（SMTP 邮件服务器）送快递时，**只看“信封（Envelope）”上写的收件人地址**，绝不拆开看你“信纸（Content）”里写了什么！但电子邮件很智能：你写邮件时只需要在信纸开头的 `To: zhangsan@seu.edu.cn`（首部）里填一次收件人，你的客户端软件（UA）就会自动帮你把这行地址抄到“信封”上去（生成 `RCPT TO` 命令），不用你填两遍！
* **【严谨考场结论】**：一个电子邮件分为**信封（Envelope）**和**内容（Content，又分为首部 Header 和主体 Body）**两大部分：
  * **信封的作用与关系**：在邮件传送过程中，**邮件传输系统（MTA / SMTP服务器）只根据“信封”上的地址信息（即 SMTP 命令 `MAIL FROM` 和 `RCPT TO` 指定的源和目的地址）来路由和投递邮件**，而不查看邮件的内容。信封对用户是透明的，由用户代理（UA）自动从邮件内容的首部提取收件人地址来生成信封。
  * **内容的作用与关系**：**邮件的内容是给最终收件人（用户）看的**。其中**首部**包含用户必须填写的 `To:`（收件人）、`Subject:`（主题）、`From:`（发件人）、`Date:`（日期）等关键字行；**主体**则是用户撰写的正文与附件，与首部之间用**一个空行**进行分隔。

### 10. `6-22` 电子邮件的地址格式是怎样的？请说明各部分的意思。
* **【严谨考场结论】**：TCP/IP 体系的电子邮件地址规定格式为：**`收件人邮箱名@邮箱所在主机的域名`**（例如 `abc@seu.edu.cn`）。
  * 符号 `@` 读作“at”（表示“在”）；
  * `@` **左侧的“收件人邮箱名（用户名）”**：在该邮件服务器管辖范围内是唯一的，标识该服务器上的特定用户信箱；
  * `@` **右侧的“邮箱所在主机的域名”**：在全球互联网范围内是唯一的，用于供发送方邮件服务器通过 DNS（查询 MX 邮件交换记录）找到接收方邮件服务器的 IP 地址。

### 11. `6-23` 试简述 SMTP 通信的三个阶段的过程。（官方大纲六(五)3）
* **【严谨考场结论】**：SMTP（简单邮件传送协议，TCP 端口 25）通信共有以下三个阶段：
  1. **连接建立阶段**：发件人的邮件送到发送方邮件服务器的发送缓存后，SMTP 客户每隔一定时间对邮件缓存扫描一次。如发现有邮件，就使用熟知端口 **25** 与**接收方邮件服务器**的 SMTP 服务器直接建立 **TCP 连接**（注意：**SMTP 不使用中间的邮件服务器中转！** 哪怕收发双方分处地球两端，也是直接建 TCP 连接）。连接建立后，接收方发出 `220 Service ready`，发送方发送 `HELO` 命令报告自己身份。
  2. **邮件传送阶段**：
     * ①发送方发 `MAIL FROM: <发件人地址>`，对方若准备好接收则回 `250 OK`；
     * ②发送方发一个或多个 `RCPT TO: <收件人地址>`（旨在先探明接收方服务器是否有该用户，避免盲目发送长邮件浪费带宽），对方回 `250 OK` 或 `550 No such user here`；
     * ③发送方发 `DATA` 命令，对方回 `354 Start mail input; end with <CRLF>.<CRLF>`；随后发送方开始传送邮件内容，最后以**单独一行的“回车换行.回车换行（`<CRLF>.<CRLF>`）”**标志邮件内容结束。
  3. **连接释放阶段**：邮件发送完毕后，SMTP 客户发送 **`QUIT`** 命令，SMTP 服务器返回 `221`（服务关闭），双方释放 TCP 连接。

### 12. `6-30` 电子邮件系统使用 TCP 传送邮件。为什么有时我们会遇到邮件发送失败的情况？为什么有时对方会收不到我们发送的邮件？
* **【说人话】**：TCP 只管“只要两台电脑连得上，就能把字节流原封不动送过去”；但如果对方邮箱容量满了、对方你名字写错了查无此人、对方邮件服务器关机维护了、或者你的邮件被对面当成垃圾邮件直接拦截扔进垃圾箱了，TCP 可替你背不了这个锅！
* **【严谨考场结论】**：TCP 只能保证在两个已成功建立连接的端点之间可靠地传输字节流，但无法解决应用层及网络可达性层面的逻辑故障：
  1. **收件人邮箱地址拼写错误**（域名不存在导致 DNS 解析失败，或用户名在对方服务器上不存在被拒绝）；
  2. **接收方邮件服务器宕机故障、网络中断**，或发送方在规定重试时间内始终无法与对方服务器建立 TCP 连接；
  3. **收件人的邮箱存储空间已满**，无法写入新邮件；
  4. **安全策略拦截**：被接收方邮件服务器的反垃圾邮件系统（Anti-Spam）或防火墙判定为垃圾邮件/含病毒附件而直接静默丢弃或放入隔离区。

### 13. `6-31` 基于万维网的电子邮件系统（Webmail，如网页版网易邮箱、QQ邮箱）有什么特点？在传送邮件时使用什么协议？（超高频单选题必考坑点！）
* **【说人话】**：千万背熟这张协议接力图！
  * **普通客户端软件（如 Outlook）发信收信**：发信用 **SMTP** $\rightarrow$ 服务器间传信用 **SMTP** $\rightarrow$ 收信用 **POP3 / IMAP**。
  * **打开浏览器网页（Webmail）发信收信**：因为你用的是**万维网浏览器**，所以从你的浏览器到你的邮箱服务器（发信）用的是 **HTTP（或 HTTPS）**！从收件人的邮箱服务器到收件人的浏览器（看信）用的也是 **HTTP（或 HTTPS）**！**只有中间“从新浪邮件服务器传给网易邮件服务器”这一段，用的才是 SMTP！**
* **【严谨考场结论】**：
  * **主要特点**：用户无需在本地计算机上安装专门的电子邮件客户端软件（用户代理 UA 就是普通的**万维网浏览器**），只要能上网打开浏览器登录邮箱网站，即可在任何地点收发和管理邮件，邮件始终保存在万维网邮件服务器上。
  * **各阶段使用的协议（必考单选！）**：
    1. **发件人从浏览器把邮件发送到发送方邮件服务器**：使用 **HTTP（或 HTTPS）协议**（而非 SMTP！）；
    2. **发送方邮件服务器把邮件传送到接收方邮件服务器**：依然使用 **SMTP 协议**；
    3. **收件人用浏览器从接收方邮件服务器读取邮件**：使用 **HTTP（或 HTTPS）协议**（而非 POP3 或 IMAP！）。

## 四、 SNMP 网络管理基本概念（共 2 题，对应官方大纲六(七)1,2）

### 14. `6-33` 什么是网络管理？为什么说网络管理是当今网络领域中的热门课题？
* **【严谨考场结论】**：**网络管理（Network Management）**包括对网络中的硬件、软件和人力的使用、综合与协调，以便监测、测试、轮询、配置、分析、评价和控制网络及网元资源，从而以合理的成本满足网络实时运行的性能、服务质量等要求（ISO 定义的**五大网络管理功能域：故障管理、配置管理、计费管理、性能管理、安全管理**）。由于现代互联网规模极其庞大且由来自不同厂商的异构设备组成，必须通过自动化的标准网管协议（SNMP）才能保障全网高可靠运行。

### 15. `6-34` 解释下列术语：网络元素、被管对象、管理进程、代理进程。（官方大纲六(七)1,2核心术语）
* **【说人话】**：网管中心的大屏幕电脑里跑着“管理进程（大总管）”，网上的每台路由器、交换机都是“网络元素（被管设备）”，每台路由器里都驻留着一个小秘书叫“代理进程”，路由器里每一个能被查看到的温度、端口状态、错包计数器都叫“被管对象”。
* **【严谨考场结论】**：
  1. **网络元素（Network Element，网元 / 被管设备）**：网络中具体被管理的硬件设备或软件构件，如路由器、以太网交换机、集线器、主机或调制解调器等。
  2. **被管对象（Managed Object）**：每一个网络元素中有许多具体的硬件部件（如某块网卡接口）或软件配置参数（如 IP 路由表项、TCP 连接数计数器），这些可供网络管理程序读取或设置的具体属性和变量称为被管对象（全部组织在 **MIB 管理信息库**中）。
  3. **管理进程（Manager，管理程序）**：运行在**网络管理工作站（管理站 NMS）**上的客户端主控程序，负责向各被管设备发出管理操作指令（如 `Get`/`Set` 探询）并接收异常告警（`Trap`），是整个网络管理系统的核心控制者。
  4. **代理进程（Agent，管理代理）**：运行在**每一个被管设备（网络元素）内部**的后台服务程序。它负责在本地维护本设备的 MIB 变量，接收并执行来自管理进程的 `Get`/`Set` 命令，并在本地发生突发异常时主动向管理进程发送 `Trap` 报文。
