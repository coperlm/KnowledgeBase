## 一、 第一类：第5至9章必背概念题（共19个核心点，“先理解后记忆”版）

### 第5章 运输层（5个核心点）
1. **`5-08` 为什么说 UDP 是面向报文的，而 TCP 是面向字节流的？（官方大纲五(二)(三)）**
   * **【底层逻辑】**：UDP 像“寄整箱快递”，你给它多大的箱子，它就贴个8字节面单原封不动发出去，既不拆分也不合并；TCP 像“拧开自来水管”，你往蓄水池（发送缓存）里倒水，TCP 根据当前管道粗细（MSS、拥塞窗口）自己决定每次接多少水装成一桶（TCP报文段）发出去。
   * **【采分关键词】**：**①UDP 面向报文**：对应用层交下来的报文，既不合并也不拆分，而是保留这些报文的边界，添加首部后直接向下交付 IP 层（因此应用程序必须选择合适大小的报文，太长会导致 IP 层分片）。**②TCP 面向字节流**：把应用程序交下来的数据仅仅看成一连串无结构的字节流，TCP 不保证接收方应用进程每次读出的数据块与发送方发出的数据块具有大小对应关系，但保证接收方收到的字节流与发送方发出的字节流完全一致。

2. **`5-09` 端口的作用是什么？为什么端口号要划分为三种？什么是套接字 Socket？（官方大纲五(一)2，`2025-选22` 原题）**
   * **【底层逻辑】**：IP 地址只能帮快递员找到“东南大学收发室（主机）”，而端口号才是找到“具体哪个寝室哪个学生（应用进程）”的房间号。
   * **【采分关键词】**：**①端口作用**：对主机内的应用进程进行寻址，实现运输层的**复用（Multiplexing）和分用（Demultiplexing）**。**②三种端口号（16位，0~65535）**：**熟知端口号（`0~1023`）**指派给最重要常见服务（如 FTP-21、TELNET-23、SMTP-25、DNS-53、HTTP-80、HTTPS-443、SNMP-161/162）；**登记端口号（`1024~49151`）**供没有熟知端口的服务器进程登记使用；**短暂端口号/客户端口号（`49152~65535`）**供客户进程运行时动态临时分配。**③套接字（Socket）**：$\text{Socket} = (\text{IP地址} : \text{端口号})$；每一条 TCP 连接唯一地被通信两端的两个端点（即**四元组：源IP、源端口、目的IP、目的端口**）所确定。

3. **`5-37` 在 TCP 拥塞控制中，什么是慢开始、拥塞避免、快重传和快恢复算法？“乘法减小”和“加法增大”各用在什么情况下？（官方大纲五(三)4，`2026-选10,11,12` 连考3题！）**
   * **【底层逻辑】**：刚上高速路不知道堵不堵，先成倍踩油门试探（慢开始 $\times 2$）；到了警戒线 `ssthresh` 就改用小步慢跑每次加1（拥塞避免 $+1$）；一旦发生**超时**说明前面彻底堵死了，立刻急刹把油门降回 `1` 重新慢开始；如果只是收到 **3个重复ACK**，说明后面的车都到了、只是中间漏了一辆车，赶紧把漏的车补发出去（快重传），油门只减半而不踩死到 `1`（快恢复）。
   * **【采分关键词】**：
     * **慢开始（Slow Start）**：当 `cwnd < ssthresh` 时使用；每经过一个传输轮次（1个 RTT），拥塞窗口 `cwnd` **按指数规律成倍增大（$\times 2$）**。
     * **拥塞避免（Congestion Avoidance / 加法增大 AI）**：当 `cwnd >= ssthresh` 时使用；每经过一个 RTT，拥塞窗口 `cwnd` **按线性规律缓慢增大（$+1\text{ MSS}$）**。
     * **发生超时重传时**：判定网络出现严重拥塞，执行**“乘法减小（MD）”**令新门限 $\text{ssthresh} = \text{当前 cwnd} / 2$，同时令 **$\text{cwnd} = 1\text{ MSS}$**，重新进入**慢开始**阶段。
     * **快重传与快恢复（收到 3 个重复 ACK 时）**：接收方收到失序报文段立即发重复确认，发送方一连收到 **3个重复 ACK** 就立即重传丢失报文段而不必等超时（**快重传**）；同时执行**快恢复**：令新门限 $\text{ssthresh} = \text{当前 cwnd} / 2$，并将新拥塞窗口直接设为 **$\text{cwnd} = \text{新 ssthresh}$**，直接转入**拥塞避免**阶段（不降为1）。

4. **`5-45` & `5-46` & `5-68`（合并精记）为什么 TCP 连接建立要用三报文握手（不能用两次）？为什么连接释放最后在 `TIME-WAIT` 状态必须等待 $2\text{MSL}$ 时间？（官方大纲五(三)2）**
   * **【底层逻辑】**：
     * **三次握手原因**：防止你昨天发出去、在网里迷路滞留的“旧连接请求”今天突然冒出来，害得服务器误以为你要建新连接而白白傻等。
     * **等待 $2\text{MSL}$ 原因**：万一你最后发给服务器的那个 `ACK` 在路上丢了，服务器收不到就会重发 `FIN`，你得在原地等够来回一趟的时间（$2\text{MSL}$）接住它的重发。
   * **【采分关键词】**：
     * **三次握手核心目的**：**防止已失效的连接请求报文段突然又传送到了服务器，因而产生错误（资源浪费）**。若采用两次握手，客户端早先发出但滞留在网络中的失效 `SYN` 到达服务器后，服务器发出确认即认为连接已建立并一直等待客户端发数据，而客户端根本不予理睬，导致服务器资源白白浪费。
     * **`TIME-WAIT` 等待 $2\text{MSL}$ 的两大理由**：**①保证客户端发送的最后一个 `ACK` 报文段能够到达服务器**（若该 `ACK` 丢失，服务器会超时重传 `FIN+ACK`，客户端在 $2\text{MSL}$ 内能收到并重传 `ACK`）；**②防止“已失效的连接请求报文段”出现在本连接中**（经过 $2\text{MSL}$ 后，本连接持续时间内产生的所有报文段都已从网络中彻底消失，不会干扰下一个新连接）。

5. **`5-74` 流量控制和拥塞控制的最主要区别是什么？发送窗口的大小取决于什么？（官方大纲五(三)4）**
   * **【采分关键词】**：
     * **主要区别**：**流量控制**是一个**端到端**的问题（只涉及发送方和接收方两端），目的是抑制发送端速率，使**接收端来得及接收**（通过接收方通告的接收窗口 `rwnd` 实现）；**拥塞控制**是一个**全局性**的问题（涉及网络中所有主机、路由器及链路），目的是防止过多的数据注入到网络中，使**网络中的路由器或链路不致过载**。
     * **发送窗口决定公式（必背）**：$$\text{发送方实际发送窗口上限} = \min(\text{接收窗口 } rwnd,\ \text{拥塞窗口 } cwnd)$$

### 第6章 应用层（6个核心点，含考纲单列的 TELNET / SNMP / P2P）
6. **`6-03` 域名系统 DNS 的解析过程是怎样的？高速缓存的作用是什么？（官方大纲六(二)，`2025-大2` 原题）**
   * **【采分关键词】**：**①解析分工**：**主机向本地域名服务器**的查询一般采用**递归查询**（替我查到底）；**本地域名服务器向根域名服务器、顶级域名服务器（如 `.cn`）、权限域名服务器**的查询通常采用**迭代查询**（告诉我下一步该找谁）；默认使用 **UDP 端口 53**（区域传送或超512字节响应时用 **TCP 53**）。**②高速缓存作用**：存放最近查询过的域名到 IP 的映射记录（受 TTL 生存时间控制），可大大减轻根和顶级域名服务器的负载，显著减少因特网上的 DNS 查询报文数量并加快解析速度。

7. **`6-05` & `6-06` 文件传送协议 FTP 的工作原理是什么？为什么说 FTP 是带外传送控制信息？TFTP 与 FTP 有何区别？（官方大纲六(三)）**
   * **【采分关键词】**：
     * **FTP 双连接机制（基于 TCP）**：FTP 使用两个并行的 TCP 连接——**①控制连接（服务器熟知端口 21）**，在整个会话期间一直保持打开，专门用于传送 FTP 客户发出的控制命令和服务器响应（因为控制信息不与文件数据走同一个连接，故称为**“带外（Out-of-Band）传送控制信息”**）；**②数据连接（服务器主动模式下使用熟知端口 20）**，仅在每次实际传输文件或目录列表时临时建立，传输完毕后立即关闭。
     * **TFTP（简单文件传送协议）对比**：TFTP 基于 **UDP（熟知端口 69）**，程序极小（适合写入网卡只读存储器 ROM 用于无盘工作站引导），不支持交互式复杂命令和用户身份鉴别，自己利用**停止-等待协议**实现每块 $512\text{ B}$ 的可靠传输。

8. **`6-07` 远程终端协议 TELNET 的主要特点是什么？什么叫作网络虚拟终端 NVT？（官方大纲六(四)单列考点！）**
   * **【底层逻辑】**：你的电脑是 Windows，远程服务器是 Linux 或大型机，双方键盘回车键、控制符编码完全不同。为了不用给世界上每两种操作系统都写一套翻译器，大家统一规定：在网线上传输时一律翻译成“网络普通话（NVT格式）”。
   * **【采分关键词】**：TELNET 是基于 **TCP（熟知端口 23）** 的客户/服务器远程登录协议。其核心是定义了**网络虚拟终端 NVT（Network Virtual Terminal）**的标准数据和控制字符格式：客户端软件把用户的按键输入转换成 **NVT 格式**通过 TCP 发送给服务器；服务器端的 TELNET 进程再把收到的 NVT 格式转换成远地主机操作系统所能理解的本地格式（返回结果时反向转换），从而**屏蔽了异构计算机系统与不同终端之间的差异**。

9. **`6-24` & `6-25` 简述电子邮件 SMTP 与 POP3/IMAP 的工作过程及区别。MIME 与 SMTP 的关系是怎样的？什么是 base64 编码？（官方大纲六(五)，`2025-选17` 原题！）**
   * **【采分关键词】**：
     * **发送（推协议 SMTP，TCP 端口 25） vs 读取（拉协议 POP3 端口 110 / IMAP）**：发送方用户代理（UA）用 **SMTP** 将邮件“推”给发送方邮件服务器，发送方服务器再用 **SMTP** 直接建立 TCP 连接“推”给接收方邮件服务器；接收方用户代理用 **POP3**（默认下载到本地后即删除服务器上邮件，或离线管理）或 **IMAP**（联机在服务器上直接管理邮件夹、可只下载邮件首部或部分附件）从接收方服务器“拉”取邮件。
     * **MIME 与 base64 编码**：传统 **SMTP 只能传送 7 位 ASCII 码文本数据**，无法直接传输二进制可执行文件、图片或中文。**MIME（通用互联网邮件扩充）**并未改动或取代 SMTP，而是在邮件首部增加了描述数据类型与编码方式的字段，利用 **base64 编码**（将每 3 个字节共 24 bit 的任意二进制数据划分为 4 组，每组 6 bit 映射为 1 个可打印的 ASCII 字符，编码后体积膨胀为原来的 $4/3 \approx 133\%$）将非 ASCII 二进制附件转换为 7 位 ASCII 文本后交由 SMTP 传输（**注意：base64 是编码，绝不是加密！**）。

10. **`6-35` 至 `6-39`（合并精记）SNMP 简单网络管理协议核心问答：为什么用 UDP？探询与陷阱（Trap）有何区别？包含哪三大构件与哪些基本操作？（官方大纲六(七)单列考点！）**
    * **【采分关键词】**：
      * **为什么用 UDP（管理站端口 162，代理端端口 161）**：网络管理绝不能过多增加网络本身的通信负载，且在**网络发生严重拥塞或故障时（此时 TCP 往往无法建立连接）**，基于无连接、单包独立发送的 UDP 反而更有可能把关键的管理命令或故障告警传送出去。
      * **三大构件**：**①SNMP 报文协议本身**（定义管理站与被管代理间交互的分组格式）；**②SMI（管理信息结构）**（规定被管对象的命名规则、数据类型和 ASN.1 编码规则）；**③MIB（管理信息库）**（采用树状层次结构组织的被管对象变量集合，只有 MIB 中的变量才能被 SNMP 读写）。
      * **核心操作与探询 vs 陷阱（Trap）**：管理进程（客户端）平时通过定期发送 **`Get-Request`（读取参数）**、**`Get-Next-Request`**、**`Set-Request`（修改配置）** 对代理进行**探询（Polling）**掌握全网常态；而当被管设备发生突发异常事件（如接口掉线、重启、温度超标）时，代理进程会主动向管理站端口 162 发送非请求型的 **`Trap`（陷阱/告警报文）**。这种“平时定期探询 + 异常主动上报 Trap”结合的方式兼顾了全面性与低带宽开销。（`Get` 报文设请求标识符是为了支持异步并发请求与应答匹配，并检测重复报文）。

11. **`6-47` P2P 应用（BitTorrent）有哪些核心工作机制？（官方大纲六(八)单列考点！）**
    * **【采分关键词】**：在 BitTorrent（BT）协议中，参与下载同一文件的所有对等方（Peer）构成一个**洪流（Torrent）**，通过 **追踪器（Tracker）** 获取其他对等方列表（或通过分布式散列表 **DHT** 实现无追踪器寻址）。文件被划分为固定大小的数据块（Chunk），采用两大核心块交换策略：**①最稀有的优先（Rarest First）**：优先请求当前邻居中副本数量最少的数据块，使稀有块尽快复制扩散；**②以牙还牙 / 针锋相对策略（Tit-for-Tat，对等方疏通算法）**：优先把数据块上传给当前正以最高数据率向自己提供数据的前4个相邻对等方，以此激励所有节点贡献上传带宽、防止“搭便车（Free-riding）”。

### 第7章 网络安全（4个核心点，官方大纲六(九)单列模块）
12. **`7-01` & `7-02` 计算机网络面临哪几种威胁？主动攻击和被动攻击的区别是什么？（官方大纲六(九)1,3）**
    * **【采分关键词】**：
      * **被动攻击（截获 Interception）**：攻击者只是观察和分析某一个协议数据单元 PDU 而不干扰信息流。包括窃听内容和**流量分析**（观察通信频度、长度、位置）。被动攻击**重点在于预防（采用数据加密）**，极难检测。
      * **主动攻击**：攻击者对某个连接中通过的 PDU 进行各种恶意处理。包括 **①篡改（Modification）**、**②恶意程序（病毒、蠕虫、木马、逻辑炸弹）**、**③伪造/假冒（Masquerading）**、**④拒绝服务（DoS / 分布式拒绝服务 DDoS，向服务器发送海量无用请求耗尽其带宽或计算资源）**、**⑤重放攻击（Replay）**。主动攻击难以完全预防，**重点在于检测（加密鉴别 + 入侵检测 IDS）与恢复**。

13. **`7-07` 至 `7-10`（合并精记）对称密码体制与公钥密码体制优缺点对比？公钥加密与数字签名的过程是怎样的？如何分配密钥？（官方大纲六(九)2，`2025-选21` 原题）**
    * **【采分关键词】**：
      * **对称密码体制（如 DES、3DES、AES）**：加密密钥与解密密钥相同（或可直接互推）。**优点**是加解密运算速度极快、效率高，适合加密海量业务数据；**缺点**是 $N$ 个用户两两通信需管理 $N(N-1)/2$ 个密钥，密钥安全分发困难（需依赖密钥分配中心 **KDC / Kerberos**），且由于收发双方持有相同密钥，**无法实现抗抵赖的数字签名**。
      * **公钥密码体制（非对称密码，如 RSA）**：使用一对数学相关的密钥——**公钥（PK）全网公开，私钥（SK）由拥有者严格保密**。**优点**是密钥管理简单，可直接实现数字签名；**缺点**是大数模幂运算极其耗时，速度远慢于对称密码（实际系统中如 TLS/PGP 均采用**“混合加密”：用 RSA 传递临时的对称会话密钥，再用对称密码 AES 加密实际数据**）。
      * **两大操作过程（严禁记混密钥角色！）**：
        * **保密通信（加密）**：发送方 A 用 **接收方 B 的公钥 $PK_B$** 加密明文 $X$ 得到密文 $E_{PK_B}(X)$ 发送；只有持有 **B 的私钥 $SK_B$** 的接收方 B 才能解密还原明文（解决**机密性**）。
        * **数字签名（抗抵赖与认证）**：发送方 A 先用密码散列函数（Hash，如 SHA-1/MD5）对报文算出定长**报文摘要**，再用 **发送方 A 自己的私钥 $SK_A$** 对摘要进行运算（签名）并附在报文后发送；任何接收方 B 用 **A 公开的公钥 $PK_A$** 验证还原出摘要，并与自己对报文重算的 Hash 摘要比对。这同时实现了三大功能：**①核实签名（身份认证，确由 A 发出）**、**②不可抵赖（除 A 外无人有 $SK_A$）**、**③报文完整性（防篡改）**。
      * **公钥分配（CA 与数字证书）**：为防止中间人用假公钥冒充，由可信第三方**认证中心 CA（Certification Authority）**用 **CA 自己的私钥**对“某实体身份 + 该实体的公钥”进行数字签名，生成 **X.509 数字证书**。

14. **`7-11` & `7-15` & `7-17` & `7-18`（合并精记）报文机密性与完整性有何区别？报文鉴别与实体鉴别有何区别？什么是重放攻击及如何防止？**
    * **【采分关键词】**：
      * **机密性 vs 完整性/鉴别**：**机密性（保密）**是防止内容被未授权者看懂（靠加密）；**报文鉴别与完整性**是验证报文确实来自所声称的发送者且在传输途中**未被篡改**（靠**密码散列函数 Hash + 报文鉴别码 MAC / 数字签名**）。
      * **报文鉴别 vs 实体鉴别**：**报文鉴别**是对所收到的**每一个单独报文**都要验证其发送者和完整性；**实体鉴别**是在系统接入或连接建立时，**一次性验证**通信对方确实是它所声称的那个实体，在后续整个连接持续期间不再重复验证。
      * **重放攻击（Replay Attack）与防御**：攻击者截获 A 发给 B 的合法加密或认证报文后，不加解密，隔一段时间原封不动地再次发送给 B 以骗取认证或重复交易。**防御措施**：在报文中加入**不重数（Nonce，每次通信随机生成且绝不重复的大随机数）**、**精确时间戳（Timestamp）**或**单调递增的序号 + 滑动接收窗口（如 IPsec ESP）**。

15. **`7-28` 试述防火墙的工作原理和所提供的功能。什么叫作网络级防火墙和应用级防火墙？（官方大纲六(九)3）**
    * **【采分关键词】**：防火墙是安插在“内部可信网络”与“外部不可信互联网”之间的特殊访问控制设备，所有进出内网的通信流都必须经过防火墙，其两大核心功能是**“阻止（禁止未授权流量通过）”和“允许（放行符合安全策略的流量）”**。分为两类：
      * **①网络级防火墙（分组过滤路由器）**：工作在**网络层和运输层**，根据分组首部中的**源/目的 IP 地址、源/目的端口号、协议类型（TCP/UDP/ICMP）、TCP 标志位（SYN/ACK）**及进出接口按访问控制列表（ACL）过滤。优点是透明、速度快；缺点是看不到应用层数据内容，无法按具体用户身份鉴别。
      * **②应用级防火墙（应用网关 / 代理服务器 Proxy）**：工作在**应用层**，每种网络应用（如 HTTP、FTP、SMTP）都必须通过专门的代理程序进行中转和深度内容审查。优点是安全性高、可做详细日志审计和用户级认证；缺点是处理开销大、转发速度较慢。

### 第8章 互联网上的音频/视频服务（2个核心点，官方大纲六(十)单列模块）
16. **`8-01` & `8-02` & `8-04` 音频/视频数据与普通文件数据有何区别？什么是时延抖动？试说明播放端缓存（播放时延）的作用。（官方大纲六(十)1,2）**
    * **【采分关键词】**：
      * **流媒体与普通文件区别**：流媒体数据量极大，采用**“边下载、边播放（Streaming）”**的工作方式；对**传输时延和时延抖动极其敏感**（实时性要求极高），但对**偶尔的少量分组丢失或误码容忍度较高**（宁可丢弃太晚到达的分组，也不使用重传机制，因此底层通常选用 **UDP** 而非 TCP）。
      * **时延抖动（Jitter）与播放缓存作用**：发送端是按恒定时间间隔（等时）发出音视频分组的，但由于互联网各分组排队时延不同，到达接收端时变成了**非等时**的，这种到达时间间隔的变化称为**时延抖动**。接收端通过设置**播放缓存（Playout Buffer）**：先将到达的分组暂存在缓存中，故意推迟一小段时间（即引入固定的**播放时延**）直到缓存积攒了一定数量的分组后，再以恒定速率按序号读出播放，从而**平滑并消除时延抖动**。

17. **`8-06` & `8-07` & `8-12` & `8-13` 流媒体服务器、元文件与 RTSP / RTP / RTCP 三大协议各起什么作用？RTP 首部为什么要使用序号和时间戳？（官方大纲六(十)2，`2025-选18` 原题！）**
    * **【采分关键词】**：
      * **元文件（Metafile）与 RTSP（实时流式协议）**：浏览器先通过 HTTP 从万维网服务器下载一个很小的描述音视频地址的**元文件**，交给本地媒体播放器；播放器再使用应用层的 **RTSP** 与媒体服务器交互。**RTSP 被称为“互联网录像机遥控协议”**，它本身**不传送音视频数据**，只是一个**带外控制协议**（既可用 TCP 也可用 UDP），专门负责控制多媒体流的**播放（Play）、暂停（Pause）、快进、快倒和结束拆除（Teardown）**。
      * **RTP（实时运输协议，封装在 UDP 之上）**：负责携带实际音视频数据块。其首部包含三个关键字段：**①序号（16位）**：每发一个 RTP 分组加 1，供接收端**检测分组丢失和恢复正确的分组次序**；**②时间戳（32位）**：反映该分组第一字节的**采样时刻**，供接收端精确计算播放时刻以**消除时延抖动并实现音频与视频同步**；**③标记（Marker）**：标志视频帧的开始或话音突发的开始。
      * **RTCP（实时运输控制协议）**：与 RTP 配合使用（通常占用不超过会话总带宽的 $5\%$），自身不传媒体数据，核心功能是：**①服务质量的监视与反馈**（向发送方周期性报告接收端的丢包率、最大时延抖动等，供发送方动态调整编码速率）；**②媒体间的同步**（绑定同一源的不同音视频流时间戳）；**③多播组成员标识**。

### 第9章 无线网络和移动网络（2个核心点，官方大纲三(五)2、三(六)3）
18. **`9-07` & `9-08` & `9-10` & `9-14` 为什么无线局域网（802.11）不能使用 CSMA/CD 而必须使用 CSMA/CA 协议和链路层确认？为什么检测到信道空闲后还要等待 DIFS？（官方大纲三(五)2）**
    * **【采分关键词】**：
      * **为什么不能用 CSMA/CD（碰撞检测）**：①无线信号随距离衰减极大，站点在自身发送信号时，本机发射功率会彻底淹没极其微弱的远方碰撞信号，硬件上难以实现“边发送边检测碰撞”（且全双工无线收发器造价过高）；②无线信道存在**隐蔽站问题（Hidden Station Problem，A 和 C 都听不见对方但同时发给中间的 B）**和暴露站问题，即使发送端本地未检测到冲突，接收端处仍可能已经发生严重冲突！
      * **为什么必须用链路层停止等待确认（ACK）**：由于无线信道误码率极高且发送方无法自己检测到碰撞，必须由接收方在正确收到数据帧、等待最短的 **SIFS** 后立即发回 **链路层 `ACK` 确认帧**，发送方超时未收到 `ACK` 则重传。
      * **为什么信道空闲还要等 DIFS 甚至退避**：等待 **DIFS** 是为了把信道优先让给具有更高优先级的控制帧（如等待 **SIFS** 的 `ACK`、`CTS` 帧）；当信道从忙刚变为空闲时，可能有多个站点同时在等待发送，因此必须再执行随机退避算法以防止所有等待站点在 DIFS 结束瞬间同时发送而必然碰撞。

19. **`9-09` & `9-11` & `9-12` & `9-25` 结合隐蔽站问题说明 RTS 和 CTS 帧的作用。SIFS、DIFS 和 NAV 各起什么作用？（`2025-选8,9` & `2026-大2` 连考两年！）**
    * **【采分关键词】**：
      * **SIFS 与 DIFS 优先级（`2025-选8`）**：**SIFS（短帧间间隔）比 DIFS（分布协调功能帧间间隔）短得多**。SIFS 用于分隔属于同一次对话的紧跟帧（如 `ACK`、`CTS` 帧），保证正在进行的传输和控制回应拥有最高优先级，不会被其他想发起新争用的普通站点（必须等更长的 DIFS）打断。
      * **RTS/CTS 预约机制与 NAV（虚拟载波侦听，`2025-选9`、`2026-大2`）**：
        * **RTS（请求发送）**：发送站 A 在等待 DIFS 后先广播一个极短的 `RTS` 帧，里面填有本次一直到收到 `ACK` 为止所需的总持续时间；
        * **CTS（允许发送）**：接收站 B（或 AP）收到后等待 SIFS，广播回复一个极短的 `CTS` 帧，里面也填有剩余所需的传输持续时间；
        * **NAV（网络分配向量 / 虚拟载波侦听）**：哪怕隐蔽站 C 听不见 A 的 `RTS`，也一定能听见接收站 B 广播的 `CTS`！所有听到 `RTS` 或 `CTS` 的其他站点都会根据帧中的持续时间字段设置本机的 **NAV 计时器**，在 **NAV 大于 0 期间，即使物理信道侦听为空闲，也严禁发起新的传输**。
        * **两大优点（且为可选机制，仅在传长数据帧时启用）**：**①有效解决隐蔽站问题**；**②大幅降低碰撞代价**（`RTS`/`CTS` 只有 20/14 字节，就算发生冲突浪费的时间极短，避免了 1500 字节长数据帧直接冲突重传的巨大浪费）。

### 第5章 运输层（10道必算母题）
1. **`5-14`（十六进制 UDP 首部拆解 —— `2025-大4` 9分真题同源母题！）**
   * **题目要点**：一个 UDP 用户数据报首部的十六进制表示为：`06 32 00 45 00 1C E2 17`。求源端口、目的端口、总长度、数据部分长度、发送方向及客户进程。
   * **开袋即食算式与答案（UDP首部共8字节，每2字节即4个十六进制数为1个字段）**：
     * **源端口号（前2字节 `0x0632`）**：$6 \times 16^2 + 3 \times 16 + 2 = 1536 + 48 + 2 =$ **$1586$**（短暂端口）；
     * **目的端口号（第3~4字节 `0x0045`）**：$4 \times 16 + 5 =$ **$69$**（熟知端口 69 对应 **TFTP 简单文件传送协议**）；
     * **UDP 用户数据报总长度（第5~6字节 `0x001C`）**：$1 \times 16 + 12 =$ **$28\text{ 字节}$**；
     * **数据部分长度**：$\text{总长度 } 28\text{ B} - \text{UDP首部 } 8\text{ B} =$ **$20\text{ 字节}$**；
     * **方向**：因源端口是短暂端口 $1586$，目的端口是熟知端口 $69$，故是**从客户发送给服务器**（TFTP进程）。

2. **`5-21`（连续 ARQ / GBN 滑动窗口序号范围推算 —— 官方大纲三(四)3,4）**
   * **题目要点**：使用连续 ARQ 协议，发送窗口大小 $W_T = 3$，序号范围是 $[0, 15]$，传输媒体保证按序到达。某一时刻接收方下一个期望收到的序号是 $5$。问：(1) 发送方的发送窗口中可能出现的序号组合有哪些？(2) 滞留在网络中的确认分组可能有哪些？
   * **开袋即食算式与答案**：
     * **(1) 发送窗口可能的序号组合**：接收方期望收到 $5$，说明序号 $4$ 及之前的分组接收方已全部收齐并发出了确认。
       * 极端情况A（接收方发出的对 $2, 3, 4$ 的确认全部还在路上未到达发送方）：发送方窗口还停留在 **`[2, 3, 4]`**；
       * 情况B（发送方刚收到对 $2$ 的确认）：窗口前移为 **`[3, 4, 5]`**；
       * 情况C（发送方刚收到对 $3$ 的确认）：窗口前移为 **`[4, 5, 6]`**；
       * 极端情况D（对 $4$ 的确认已经到达发送方）：发送方窗口最靠前可处在 **`[5, 6, 7]`**。
     * **(2) 滞留在网络中的确认分组**：可能是对序号 **`2`、`3`、`4`** 的确认（即期望序号为 $3, 4, 5$ 的 ACK；对 $0$ 和 $1$ 的确认必然早已到达发送方，否则发送方窗口根本发不出序号 $4$！）。
     * **附记 GBN 与 SR 窗口上限公式（必背）**：若用 $n$ 比特编号，**GBN（后退N帧）**发送窗口 $1 < W_T \le 2^n - 1$，接收窗口 $W_R = 1$（见 `5-19`）；**SR（选择重传）**发送窗口与接收窗口满足 $W_T = W_R \le 2^{n-1}$。

3. **`5-22` & `5-70` & `5-71`（TCP 32位序号绕回与含首部开销耗时计算 —— `2026-大6` 100%一字不差原题题源！）**

5. **`5-24`（由链路速率、传播时延与实测吞吐量反求发送窗口 $W$ —— 关联 `2026-选3`）**
   * **题目要点**：TCP 连接使用 $R = 256\text{ kbit/s}$ 链路，端到端单程传播时延 $\tau = 128\text{ ms}$（故往返 $\text{RTT} = 2\tau = 256\text{ ms} = 0.256\text{ s}$）。经测试发现实际吞吐量只有 $120\text{ kbit/s}$。试问发送窗口 $W$ 是多少？（分两种情况讨论接收端发出确认的时机）。
   * **开袋即食算式与答案**：
     * 设发送窗口为 $W$ 比特，发送整个窗口数据本身的发送时延 $T_w = \frac{W}{256 \times 10^3}$。
     * **情况一（接收端在收完第一个极小分组后就立即回确认，即忽略单帧发送时延）**：在一个往返时间 $\text{RTT} = 0.256\text{ s}$ 内发送了 $W$ 比特，故：
       $$W = 120 \times 10^3\text{ bit/s} \times 0.256\text{ s} = 30720\text{ bit} = \mathbf{3840\text{ 字节}}$$
     * **情况二（接收端在收完整个窗口 $W$ 的全部数据后才发回确认）**：则一个周期总时间为 $T_w + 2\tau = \frac{W}{256\text{ k}} + 0.256\text{ s}$，由 $\frac{W}{\frac{W}{256\text{ k}} + 0.256} = 120\text{ k}$ 解得：
       $$W \approx 57788\text{ bit} \approx \mathbf{7224\text{ 字节}}$$

6. **`5-33`（谢书标准 TCP 超时重传时间 $RTO$ 加权平均计算公式）**
   * **题目要点**：开始建立连接时设定初始 $RTO = 6\text{ s}$。(1) 收到连接确认报文段时，首次测出 $RTT$ 样本值为 $1.5\text{ s}$，求现在的 $RTO$ 值；(2) 接着发数据段并收到确认，第二次测出 $RTT$ 样本值为 $2.5\text{ s}$，求现在的 $RTO$ 值。（取标准权值 $\alpha = 1/8 = 0.125$，$\beta = 1/4 = 0.25$）。
   * **开袋即食公式与答案（背熟这3个递推公式）**：
     * **首次测量初始化规则**：$$RTT_{S1} = RTT_1, \quad RTT_{D1} = \frac{RTT_1}{2}, \quad RTO = RTT_S + 4 \times RTT_D$$
       * 故第(1)问：$RTT_{S1} = 1.5\text{ s}$，$RTT_{D1} = 1.5 / 2 = 0.75\text{ s}$，得 **$\text{RTO}_1 = 1.5 + 4 \times 0.75 = \mathbf{4.5\text{ s}}$**。
     * **后续测量更新公式**：
       $$RTT_{S\text{新}} = (1 - \alpha) RTT_{S\text{旧}} + \alpha \cdot RTT_{\text{新样本}} = \frac{7}{8} RTT_{S\text{旧}} + \frac{1}{8} RTT_{\text{新样本}}$$
       $$RTT_{D\text{新}} = (1 - \beta) RTT_{D\text{旧}} + \beta \cdot |RTT_{S\text{旧}} - RTT_{\text{新样本}}| = \frac{3}{4} RTT_{D\text{旧}} + \frac{1}{4} |RTT_{S\text{旧}} - RTT_{\text{新样本}}|$$
       * 故第(2)问（代入 $RTT_2 = 2.5\text{ s}$）：
         * $RTT_{S2} = \frac{7}{8} \times 1.5 + \frac{1}{8} \times 2.5 = 1.3125 + 0.3125 = \mathbf{1.625\text{ s}}$；
         * $RTT_{D2} = \frac{3}{4} \times 0.75 + \frac{1}{4} \times |1.5 - 2.5| = 0.5625 + 0.25 = \mathbf{0.8125\text{ s}}$；
         * **$\text{RTO}_2 = 1.625 + 4 \times 0.8125 = 1.625 + 3.25 = \mathbf{4.875\text{ s}}$**。

8. **`5-51`（UDP 检验和特殊全0/全1取值规则 —— `2025-选23` 100%原题！）**

   * **开袋即食标准答案**：
     * **(1) 不使用检验和**：填入**全 0**（即 `0x0000`）；
     * **(2) 使用检验和且算出结果为全 1**：正常填入**全 1**（即 `0xFFFF`）；
     * **(3) 使用检验和但算出结果恰好为全 0**：**必须改填为全 1（即 `0xFFFF`）发送！**（因为在二进制反码算术中，全 0 和全 1 都代表数值 $0$，而全 0 已被专门规定用来表示“未启用检验和”，故算得全 0 时必须发全 1 以免接收方误认为没用检验和）。

9. **`5-61`（TCP 发送窗口前沿、后沿与可用窗口动态追踪）**
   * **题目要点**：A向B发 $3\text{ KB}$（$3072\text{ B}$，字节号 $0 \sim 3071$）数据，发送窗口大小固定为 $2\text{ KB}$（$2048\text{ B}$），初始序号为 $0$。依次求8种事件下的窗口位置与可用窗口大小。
   * **开袋即食核对结论**：记住两个不变量——**窗口后沿 = 已收到的最大确认号 `ack`**；**窗口前沿 = 窗口后沿 + 窗口大小 $2048$**；**可用窗口 = 窗口前沿 - 下一个待发送字节序号**。
     * (1) 发 $1\text{ KB}$（$0 \sim 1023$）：窗口覆盖 $[0, 2047]$，已发未确认 $1024\text{ B}$，**可用窗口还剩 $1024\text{ B}$**（字节 $1024 \sim 2047$）；
     * (2) 把发送窗口用完（发完 $0 \sim 2047$）：窗口仍为 $[0, 2047]$，**可用窗口 = $0$**；
     * (3) 收到对第 $1000$ 号字节的确认（即 `ack = 1001`，注意第1000号字节本身已确认，共确认了 $0 \sim 1000$ 共 $1001\text{ B}$）：窗口后沿移至 $1001$，前沿移至 $1001 + 2048 - 1 = 3048$，**可用窗口 = $3049 - 2048 = 1001\text{ B}$**；
     * (4) 再发 $850\text{ B}$：**可用窗口 = $1001 - 850 = 151\text{ B}$**；
     * (5) 收到 `ack = 900`：属于**迟到的旧重复确认（$< 1001$），直接忽略，窗口不动**！

10. **`6-14`（HTTP/1.0 与 HTTP/1.1 持久/非持久连接正误辨析 —— `2026-选15` 原题模型）**
    * **题目要点**：判断正误并说明理由：(1) 网页含1个文本和3张图片，用户发1个请求即可收到4个响应报文；(2) 同一服务器上的两个网页 `www.abc.com/m1.html` 和 `m2.html` 可使用同一个 HTTP/1.1 持续连接传送；(3) 非持续连接只需1个 TCP 报文段就能装入两个不同的 HTTP 请求报文；(4) HTTP 响应报文中的主体实体部分永远不会是空的。
    * **开袋即食标准答案**：
      * **(1) 错误**：HTTP 是请求/响应模式，1个文本 + 3张图片共 **4个独立对象，客户必须发送 4 个 HTTP 请求报文**才能收到 4 个响应报文。
      * **(2) 正确**：HTTP/1.1 默认采用**持续连接（Persistent Connection）**，只要两个网页位于同一台服务器上，服务器在发送完第一个响应后保持该 TCP 连接打开，后续请求和响应可继续复用同一条 TCP 连接。
      * **(3) 错误**：**非持续连接（HTTP/1.0 默认）每个对象的传输都必须单独建立一条全新的 TCP 连接**，传完1个对象就关闭连接，绝不可能把两个不同请求塞进同一个 TCP 报文段。
      * **(4) 错误**：例如对 `HEAD` 方法的响应、或状态码为 `204 No Content`、`304 Not Modified` 的响应报文，其实体主体部分就是**空的**。

11. **`6-15` & `6-16`（DNS 解析 + TCP 握手 + HTTP 1.0/1.1 三种连接方式总耗时 RTT 计算）**
    * **题目要点**：点击一个 URL，本地无 DNS 缓存，依次经 $n$ 个 DNS 服务器耗时 $\text{RTT}_1 + \text{RTT}_2 + \dots + \text{RTT}_n$（记为 $\text{RTT}_{\text{DNS}}$）。Web 服务器的往返时间为 $\text{RTT}_w$，HTML 主文件里又链接了 **3个非常小的图片对象**，忽略对象发送时间。求从点击 URL 到全部显示在屏幕上所需总时间：
      * `6-15`：只读取 HTML 本身（不含那3个小对象）；
      * `6-16(1)`：没有并行 TCP 连接的非持续 HTTP；
      * `6-16(2)`：使用并行 TCP 连接（设最多可并行开3个以上连接）的非持续 HTTP；
      * `6-16(3)`：流水线方式（Pipelining）的持续 HTTP（HTTP/1.1）。
    * **开袋即食万能公式与答案（背熟每个对象耗几个 $\text{RTT}_w$）**：
      * **预备知识**：每次新建 TCP 连接（三次握手）耗时 **$1\text{ RTT}_w$**（第三次握手可捎带发送 HTTP 请求），请求发过去到响应回来耗时 **$1\text{ RTT}_w$**。
      * **`6-15`（仅获取 HTML 基础页）**：$$\text{总时间} = \text{RTT}_{\text{DNS}} + 1\text{ RTT}_w\text{（TCP握手）} + 1\text{ RTT}_w\text{（请求并收到HTML）} = \mathbf{\text{RTT}_{\text{DNS}} + 2\text{ RTT}_w}$$
      * **`6-16(1)` 串行非持续 HTTP（获取 HTML + 3个小对象，共4个对象，每个都要新建TCP连接耗 $2\text{ RTT}_w$）**：
        $$\text{总时间} = \text{RTT}_{\text{DNS}} + 2\text{ RTT}_w\text{（HTML）} + 3 \times 2\text{ RTT}_w\text{（串行取3个对象）} = \mathbf{\text{RTT}_{\text{DNS}} + 8\text{ RTT}_w}$$
      * **`6-16(2)` 并行非持续 HTTP（拿到 HTML 后，同时并行发起 3 条 TCP 连接去取 3 个对象）**：
        $$\text{总时间} = \text{RTT}_{\text{DNS}} + 2\text{ RTT}_w\text{（HTML）} + 2\text{ RTT}_w\text{（3条并行连接同时握手+取回）} = \mathbf{\text{RTT}_{\text{DNS}} + 4\text{ RTT}_w}$$
      * **`6-16(3)` 持续连接（Persistent HTTP，全程只建 1 次 TCP 连接）**：
        * **流水线方式（Pipelining）**：拿到 HTML 后，一口气连续发出3个对象的请求，只需 **1个 $\text{RTT}_w$** 就能把3个对象全部取回：
          $$\text{总时间（流水线）} = \text{RTT}_{\text{DNS}} + 2\text{ RTT}_w\text{（握手+HTML）} + 1\text{ RTT}_w\text{（流水线取3个对象）} = \mathbf{\text{RTT}_{\text{DNS}} + 3\text{ RTT}_w}$$
        * *(补充：若是**非流水线方式**的持续连接，3个对象虽不用重握手，但需一问一答耗 $3\text{ RTT}_w$，总时间为 $\text{RTT}_{\text{DNS}} + 5\text{ RTT}_w$)*。

12. **`6-32`（DHCP 作用与 DORA 四步过程 —— `2025-选16` 原题！）**
    * **题目要点**：DHCP 协议用在什么情况下？刚开机的主机 ROM 中有没有 IP、子网掩码和 DNS 地址？
    * **开袋即食标准答案**：当主机需要自动获取动态配置参数（即插即用）时使用 DHCP（基于 **UDP，客户端口 68，服务器端口 67**）。刚开机的主机 ROM 中**没有任何 IP 地址、子网掩码、默认网关或 DNS 服务器地址**（只有网卡 ROM 里的 MAC 地址）。它通过 **DORA 四步广播/单播过程**获取配置：**`DHCPDISCOVER`（发现，源IP `0.0.0.0`，目的IP `255.255.255.255` 广播） $\rightarrow$ `DHCPOFFER`（提供） $\rightarrow$ `DHCPREQUEST`（请求） $\rightarrow$ `DHCPACK`（确认）**。

13. **`6-46`（图6-37 全协议栈分层与 TCP/UDP 归属总盘点 —— `2026-选13` 直接题源！）**
    * **题目要点**：看教材 P332 图6-37：(1) 为什么有的应用层协议用 TCP 而有的用 UDP？(2) 为什么 MIME 画在 SMTP 之上？(3) 为什么路由选择协议 RIP（及 BGP）画在应用层？
    * **开袋即食标准答案（务必把图6-37这张框图印在脑子里！）**：
      * **(1) TCP vs UDP 归属总表（考场秒选必背）**：
        * **使用 TCP 的协议**：**`BGP`（179）、`FTP`（20/21）、`TELNET`（23）、`HTTP`（80）、`HTTPS`（443）、`SMTP`（25）、`POP3`（110）、`IMAP`** —— 要求可靠传输大量数据或文件，不允许丢包差错。
        * **使用 UDP 的协议**：**`SNMP`（161/162）、`TFTP`（69）、`DNS`（53，主用UDP，区域传送/大响应兼支TCP！）、`RIP`（520）、`DHCP`（67/68）、`RTP/RTCP`** —— 多数是短小的请求/应答查询或实时流媒体，要求低时延、无连接开销。
        * **直接使用 IP 封装的协议**：**`ICMP`、`IGMP`、`OSPF`（协议号89）**。
      * **(2) 为什么 MIME 在 SMTP 之上**：MIME 负责把非 ASCII 二进制数据编码转换成 7 位 ASCII 码文本，然后再交给下层的 SMTP 去发送。
      * **(3) 为什么 RIP/BGP 画在应用层**：虽然它们为网络层路由表服务，但它们在实现时直接作为应用进程运行，**利用了运输层协议（RIP 用 UDP 520 端口，BGP 用 TCP 179 端口）提供的服务**来交换路由报文。

14. **`6-51`（客户/服务器 C/S 与 P2P 文件分发最短时间计算 —— `2025-选20` 100%原题！）**
    * **题目要点**：服务器有一文件 $F = 15\text{ Gbit}$ 要分发给 $N$ 个对等方。服务器上传速率 $u_s = 30\text{ Mbit/s}$，每个对等方下载速率 $d = 2\text{ Mbit/s}$，上传速率 $u = 300\text{ kbit/s} = 0.3\text{ Mbit/s}$。分别计算在 (1) $N = 10$；(2) $N = 1000$ 时，C/S 方式和 P2P 方式下分发时间的最小值。
    * **开袋即食公式与答案（背熟这两个 `max` 公式）**：
      * 单位统一：$F = 15 \times 10^3\text{ Mbit} = 15000\text{ Mbit}$，$u_s = 30\text{ Mbit/s}$，$d_{\min} = 2\text{ Mbit/s}$，$u = 0.3\text{ Mbit/s}$。
      * **一、C/S 模式最短时间公式**：$$D_{\text{CS}} = \max\left(\frac{N \cdot F}{u_s},\ \frac{F}{d_{\min}}\right)$$
        * 当 $N = 10$ 时：$D_{\text{CS}} = \max\left(\frac{10 \times 15000}{30},\ \frac{15000}{2}\right) = \max(5000,\ 7500) = \mathbf{7500\text{ s}}$；
        * 当 $N = 1000$ 时：$D_{\text{CS}} = \max\left(\frac{1000 \times 15000}{30},\ 7500\right) = \max(500000,\ 7500) = \mathbf{500000\text{ s}}$（随 $N$ 线性暴增！）。
      * **二、P2P 模式最短时间公式**：$$D_{\text{P2P}} = \max\left(\frac{F}{u_s},\ \frac{F}{d_{\min}},\ \frac{N \cdot F}{u_s + N \cdot u}\right)$$
        * 当 $N = 10$ 时：$\frac{F}{u_s} = 500\text{ s}$，$\frac{F}{d_{\min}} = 7500\text{ s}$，$\frac{10 \times 15000}{30 + 10 \times 0.3} = \frac{150000}{33} \approx 4545.5\text{ s} \Rightarrow D_{\text{P2P}} = \max(500,\ 7500,\ 4545.5) = \mathbf{7500\text{ s}}$；
        * 当 $N = 1000$ 时：$\frac{1000 \times 15000}{30 + 1000 \times 0.3} = \frac{15000000}{330} \approx 45454.5\text{ s} \Rightarrow D_{\text{P2P}} = \max(500,\ 7500,\ 45454.5) = \mathbf{45455\text{ s}}$（仅需 C/S 方式的约 $1/11$ 时间！）。

### 第7章至第9章（5道必算/必析母题，100%命中2025/2026真题）
15. **`7-19`（对称密钥实体鉴别中的反射/重放攻击漏洞分析）**
    * **题目要点**：A 和 B 共享密钥 $K_{AB}$。入侵者 P 截获通信并冒充 B 给 A 发：“我是 B，不重数 $R_A$”。A 收到后要求对方用 $K_{AB}$ 加密 $R_A$，同时发给对方另一个不重数。但 P 根本没有 $K_{AB}$，于是 P 直接拿相同的 $R_A$ 作为自己的不重数发回给 A。A 收到后老老实实算出 $K_{AB}(R_A)$ 发给 P，P 就拿这个现成的密文骗过了 A！问 A 能否避免这样的错误？
    * **开袋即食标准答案**：**能避免！** 漏洞原因在于 A 和 B 使用了完全对称相同的质询格式，且 A 允许对方发来与自己刚才发出的完全相同的随机数 $R_A$。**改进措施**：①严禁接收与自己刚发出的不重数相同的随机数（发现 $R_B == R_A$ 立即报警断开）；②在加密块中加入**方向标识符或发送方身份 ID**（如 $K_{AB}(A, R_A)$ 与 $K_{AB}(B, R_A)$），或者 A 用奇数做不重数、B 用偶数做不重数，使 P 无法将 A 加密的结果反射回来冒充 B 的回答。

16. **`7-24`（TCP 重传与 IPsec ESP 防重放序号关系 —— `2025-选6` 同源考点！）**
    * **题目要点**：在 TCP 连接上使用 IPsec 通信。若有一个 TCP 报文段丢失了，后来 TCP 重传该序号的报文段时，相应的 IPsec 安全数据报是否也要使用同样的 IPsec 序号呢？
    * **开袋即食标准答案**：**绝对不能使用同样的 IPsec 序号，必须分配一个新的、递增的 IPsec 序号！**
      * **理由**：网络层的 IPsec 对上层 TCP 是完全透明的，IPsec 根本不知道也不关心载荷里装的是新发的 TCP 段还是重传的 TCP 段；更为关键的是，**IPsec 的 AH 和 ESP 首部使用单调递增的序号和滑动接收窗口来防止重放攻击（Replay Attack）**。如果重传时使用旧的 IPsec 序号，接收端的 IPsec 模块会误认为这是一个被攻击者截获重放的重复分组（或已落入滑动窗口左侧）而直接将其丢弃！

17. **`8-21`（加权公平排队 WFQ 调度顺序推算 —— `2025-选5` 逐字节公平排队同源母题！）**
    * **题目要点**：缓存运行加权公平排队 WFQ 调度策略，第1、2、3类分组权重分别是 $0.5,\ 0.25,\ 0.25$（即比例为 $2 : 1 : 1$）。(1) 若三种类别在缓存中都有大量分组，以何种顺序接受服务？(2) 若只有第1类和第3类有大量分组而第2类为空，以何种顺序接受服务？
    * **开袋即食标准答案**：
      * **(1) 三类均非空**：按权重比 $0.5 : 0.25 : 0.25 = 2 : 1 : 1$ 循环调度，故服务顺序为 **`1, 2, 1, 3, 1, 2, 1, 3...`**（或 **`1, 1, 2, 3, 1, 1, 2, 3...`**，每4个周期中第1类占2次，第2、3类各占1次）。
      * **(2) 第2类为空（工作保守性 Work-Conserving）**：WFQ 不会让链路在有包可发时闲置，剩余的第1类和第3类按其原有权重比 $0.5 : 0.25 = 2 : 1$ 瓜分带宽，故服务顺序变为 **`1, 1, 3, 1, 1, 3...`**。
      * *(附记 `2025-选5` 逐字节公平排队算法：当各队列权重相等但分组字节长度不同时，用每个分组所在队列的**累计字节长度**作为该分组的“虚拟完结轮次”，将所有队列的分组按**完结轮次从小到大**排序即为输出顺序；若完结轮次相同，则按输入端口号 $1 \rightarrow 2 \rightarrow 3$ 排序！)*

18. **`8-34`（流媒体播放缓存消除时延抖动计算 —— 官方大纲六(十)核心计算！）**
    * **题目要点**：看教材 P404 图8-29：发送方在 $t = 1, 2, 3, 4, 5, 6, 7, 8$ 等时发送 8 个话音分组。从图中读出第 1 至第 8 个分组到达接收方的时刻依次为：$t_{\text{arr}} = 8,\ 9,\ 12,\ 12,\ 12,\ 15,\ 15,\ 16$。问：(1) 分组 2 到分组 8 经历的网络时延各为多少？(2) 若接收方在收到第1个分组的 $t = 8$ 时刻就立即开始等时播放（即要求在 $t = 8, 9, 10, 11, 12, 13, 14, 15$ 播放分组 $1 \sim 8$），有哪几个分组未能按时赶上播放？(3) 若要所有 8 个分组都能按时赶上播放，接收方最起码应在什么时间开始播放？
    * **开袋即食算式与答案**：
      * **(1) 各分组经历的网络时延（$\text{到达时刻} - \text{发送时刻}$）**：
        * 分组1：$8 - 1 = 7$；
        * **分组2**：$9 - 2 =$ **$7$**；
        * **分组3**：$12 - 3 =$ **$9$**；
        * **分组4**：$12 - 4 =$ **$8$**；
        * **分组5**：$12 - 5 =$ **$7$**；
        * **分组6**：$15 - 6 =$ **$9$**；
        * **分组7**：$15 - 7 =$ **$8$**；
        * **分组8**：$16 - 8 =$ **$8$**。
      * **(2) 若在 $t = 8$ 立即开始播放**：
        * 分组3本应在 $t = 10$ 播放，但它在 $t = 12$ 才到达（迟到！）；
        * 分组4本应在 $t = 11$ 播放，但它在 $t = 12$ 才到达（迟到！）；
        * 分组6本应在 $t = 13$ 播放，但它在 $t = 15$ 才到达（迟到！）；
        * 分组7本应在 $t = 14$ 播放，但它在 $t = 15$ 才到达（迟到！）；
        * 分组8本应在 $t = 15$ 播放，但它在 $t = 16$ 才到达（迟到！）；
        * 故未能按时赶上播放的有 **分组 3、4、6、7、8（共 5 个分组）**！
      * **(3) 全部赶上播放的最早开播时间**：找出所有分组中经历的**最大网络时延 $D_{\max} = \max(7, 7, 9, 8, 7, 9, 8, 8) = 9$ 个时间单位**（发生在分组3和分组6上）。因此端到端恒定播放时延必须至少设为 $9$，即第1个分组（在 $t=1$ 发出）必须在 **$t = 1 + 9 = 10$** 时才开始播放（此时分组 $1 \sim 8$ 分别在 $t = 10, 11, 12, 13, 14, 15, 16, 17$ 播放，所有分组在播放时刻前均已到达缓存！）。

19. **`9-26`（802.11b 使用 RTS/CTS 发送数据帧总时间计算 —— `2026-大2` 100%原题题源！）**
    * **题目要点**：使用 `802.11b` 协议的站要发送 $1000\text{ B}$ 长的数据帧（已含首尾），并使用 RTS 和 CTS 帧。试计算从决定发送帧（等待 DIFS）一直到收到确认帧所经历的总时间（忽略传播时间和误码率）。
      * *(注：谢书 `9.1.3` 节给出的 802.11b 默认标准参数为：$\text{DIFS} = 50\ \mu\text{s}$，$\text{SIFS} = 10\ \mu\text{s}$，控制帧 RTS = $20\text{ B}$、CTS = $14\text{ B}$、ACK = $14\text{ B}$ 按基本速率 $1\text{ Mbit/s}$ 发送，数据帧按 $11\text{ Mbit/s}$ 发送 —— **你看，这组参数跟 `2026-大2` 真题题干给的参数一模一样，真题只是把数据帧长度从 1000B 改成了 1500B！**)*
    * **开袋即食算式与答案**：
      * $\text{RTS 发送时间} = \frac{20 \times 8\text{ bit}}{1\text{ Mbit/s}} = 160\ \mu\text{s}$；
      * $\text{CTS 发送时间} = \frac{14 \times 8\text{ bit}}{1\text{ Mbit/s}} = 112\ \mu\text{s}$；
      * $\text{ACK 发送时间} = \frac{14 \times 8\text{ bit}}{1\text{ Mbit/s}} = 112\ \mu\text{s}$；
      * $\text{DATA 发送时间（1000B）} = \frac{1000 \times 8\text{ bit}}{11\text{ Mbit/s}} \approx 727.3\ \mu\text{s}$（若按谢书假定全部帧都用 $11\text{ Mbit/s}$ 算，还要加上每帧 $192\ \mu\text{s}$ 的物理层 PLCP 前同步码开销；而在考研卷如 `2026-大2` 中，直接按题干给定的基本速率与数据速率相除相加即可）：
      * **总时间公式（1个 DIFS + 3个 SIFS + 4个帧发送时间）**：
        $$T_{\text{total}} = \text{DIFS} + T_{\text{RTS}} + \text{SIFS} + T_{\text{CTS}} + \text{SIFS} + T_{\text{DATA}} + \text{SIFS} + T_{\text{ACK}}$$
        $$= 50 + 160 + 10 + 112 + 10 + 727.3 + 10 + 112 = \mathbf{1191.3\ \mu\text{s}}$$
      * **顺手必记 NAV 公式（`2026-大2(1)` 考到）**：
        * $\text{NAV}(\text{RTS}) = 3 \times \text{SIFS} + T_{\text{CTS}} + T_{\text{DATA}} + T_{\text{ACK}}$；
        * $\text{NAV}(\text{CTS}) = 2 \times \text{SIFS} + T_{\text{DATA}} + T_{\text{ACK}}$。
